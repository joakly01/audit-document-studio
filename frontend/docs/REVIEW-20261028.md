# 全面复核与联调准备 · 2026-10-28

## 结论与范围

本轮以 Git `bddd108` 为基线，对 11 个工具、资料管理、任务中心、提取模板和提示词库进行检查。保持已经确认的布局与操作名称，主要修复真实接口、慢网络和连续操作下容易出现的问题。

**前端回归通过不等于真实联调完成。** 当前没有接入真实业务后端、身份凭证或模型服务，不能承诺一次联调全部通过。本轮修复不要求改变既有后端接口；专用接口地址、历史快照、费用单位等仍需双方确认。

本轮未提交 Git、更新服务器或生成部署包。线上现有版本不包含以下新增修复。

## 本轮发现与处理

| 问题 | 用户影响 | 修复 |
|---|---|---|
| 文件夹层级在界面和 API adapter 重复创建 | 新目录上传失败，或重复嵌套目录 | 界面仅传目标目录与相对路径，由 adapter 创建一次层级；演示模式采用相同语义 |
| 新建目录未记录空间 | 新建个人目录不能立即上传子文件夹；返回资料可能误标公共空间 | 创建时缓存空间，上传结果保留所属空间 |
| 目录/空间查询失败保留旧内容 | 标题显示乙目录，列表却是甲目录，容易误选 | 切目录清理旧文件；空间切换及失败清理失效目录；错误显式展示 |
| 全页选择返回时用户已切换范围 | 旧目录文件被意外加入或移除 | 资料管理、添加资料窗口均取消过期范围请求；手工改选也使旧请求失效 |
| 附件确认中取消窗口仍写入结果 | 用户取消后附件关系被修改 | 确认增加等待状态，关闭、切换主文件、卸载后旧响应失效；资料库与工具保存期间禁止再次编辑同一文件 |
| 附件加载/保存期间切换工具 | 旧窗口重新打开，或结果写进另一工具草稿 | 打开请求区分次序；保存绑定原草稿和原文件，检查文件仍存在 |
| 提交任务后关闭窗口并切换工具 | 旧任务响应把用户强行带离新工具 | 仅仍在原操作上下文时自动进入结果；任务已创建时明确提示可从任务中心查看 |
| 导出返回带业务错误的 `+json` 响应 | 可能被当作文件下载 | 识别 JSON 内容类型中的业务错误 |
| 接口地址已有查询参数时继续加参数 | 产生两个 `?`，后端收不到正确参数 | 正确使用 `&` 追加 |

文件分页特别验证：等待响应期间保留原总数，避免分页组件自动回到第 1 页；加载成功/失败后再更新总数。移除原文区添加入口、左侧主按钮强调、任务中心三个操作、默认提取模板为空等既有设计保持。

## 继续复核：目录生命周期与任务信息

在首轮基础上，继续复现并修复以下边界，保持既有页面布局、按钮和业务流程：

- **目录改名/删除后再上传**：原目录创建缓存长期保留，会将下一次文件上传到旧目录 ID。现在仅合并正在进行的同路径查询，完成后释放；再次上传重新查找目录。覆盖本页面改名、删除，以及其他会话删除目录；并发上传同一路径仍只建一次目录。
- **错误文件下载**：补充识别不含业务 `code` 的 `application/problem+json`；即使错误被网关包装成 HTTP 200，也显示错误原因而不保存为结果文件。合法 JSON 结果仍可导出。
- **参数校验提示**：支持 `detail` 数组中的字段和原因，不再显示 `[object Object]`；不输出响应中的原始输入数据。
- **任务信息串用**：连续点击不同任务时，只有最后一次请求能打开窗口；关闭窗口、切换记录范围或离开页面时旧请求失效。避免查看乙任务却被甲任务慢响应覆盖。
- **任务查询失败**：清理上一查询的列表与总数，并展示错误，避免旧分析记录冒充当前筛选结果。

新增 `tests/review-boundaries.test.ts`（7 项，修复前 5 项失败，2 项用于保留并发/正常导出行为）和 `tests/browser-task-boundaries.mjs`（3 项，修复前三项均失败）。任务快照复制、结果来源与原文预览已有防护继续保留，本次未调整后端接口。

## 建议联调顺序与验收线

1. **资料链路**：目录 → 上传单文件/子文件夹 → 解析 → 本页/全部页选择 → 原文与解析文本 → 附件。先做 1 份，再做跨目录多份；校验后台真实目录无重复嵌套。
2. **基础任务链路**：信息提取先走通创建 → 轮询 → 结果 → 来源 → 导出 → 再次分析，验证保存的提示词正文、字段和附件就是提交时的快照。
3. **逐工具确认结果**：词云看词频与来源；主题看资料要点与归纳；时间轴看日期与事项；会议看时间轴/议题聚类与筛选；风险看等级/依据；合同看检查项与报告；招投标看项目/单位/规则；费用看约定和计算；工程看重复/主子项目；两表看匹配/差异/双侧未匹配。
4. **异常与并发**：断网、超时、权限变化、资料删除、任务部分失败、快速切工具和关闭弹窗。创建请求超时不自动重发，先查任务记录；建议后端提供幂等键支持。
5. **容量**：按真实业务规模测试文件数、文件大小、页数、结果行数和同时运行任务数；记录耗时、失败率、队列情况。前端页面不卡不代表模型调度容量已通过。

通过标准：每个工具均有可复现的真实提交与结果样本；结果能追溯到正确资料；导出可打开且内容完整；权限/错误不会被当成功；切页切工具不串数据；再次分析不改旧结果。未配置能力应保持明确禁用或提示，不能以演示数据代替验收。
