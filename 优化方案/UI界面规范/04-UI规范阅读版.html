版本：1.3　｜　核对日期：2026-10-19　｜　用途：产品评审、界面设计、前端实施与验收

总原则：高频任务直达，低频功能收纳；文字清楚、操作常规，把主要空间留给资料和审计结果。

1. 适用范围与使用顺序

适用于资料管理、任务中心、提取模板及全部 11 项分析工具，包括添加资料、配置、运行、结果、原文核验、导出和权限相关界面。覆盖桌面及窄屏使用；屏幕界面的字号、布局与导出公文的排版分别管理。

本规范已合并08–15号补充中的有效规则，作为本轮统一基线。执行顺序：用户最新明确要求 → 本主规范及设计变量/验收清单 → 各工具业务核对说明。08–15号文档保留追溯，不再作为互相竞争的独立规范；旧PDF与截图仅代表其历史版本。功能和权限以核对过的原系统能力及后台授权为准。

文中的“必须”是验收要求，“建议”是默认设计值。规范要求与现有实现完成度分开记录，不以发布规范代替逐页验收。当前已验证范围及待整改项见第 17 节。

配套文件：验收清单、设计变量、可视化阅读版、图标规范、图标速查。

2. 信息与操作的优先级

层级 判断依据 展示方式 本系统中的应用
核心任务 当前页面要完成的主要目标 明确的主按钮、主要内容区 上传、开始提取/开始分析、查看结果
高频辅助 经常使用、影响任务效率 直接可见的次按钮或搜索框 添加资料、名称搜索、当前结果筛选
按需使用 不应持续占用核心区域 更多菜单、行内省略号、详情 文本检索、上传记录、移动、重新解析、目录管理
背景说明 解释结构或能力，通常无需立即判断 详情、提示、按需展开 项目目录类型、完整权限说明、高级参数
异常状态 影响当前操作，需要立即知晓 简短状态、局部提示与恢复入口 只读、解析失败、缺少原文、部分失败

UI-01：每个独立任务区域原则上只有一个实心主按钮。 不把所有功能做成同等大小、同等颜色的按钮；页面级操作、所选资料操作、单行操作必须分清对象。

UI-02：操作栏空间不足时，优先收纳，不能以缩小文字或增加按钮行数换取容纳量。 表单字段、说明文字和正文可以正常换行；主命令栏与资料工具栏保持单行。极窄屏下保留任务主入口，其余进入菜单。

UI-03：同一区域不重复提供相同操作。 资料管理的文本检索仅在“更多”第一项；上传记录同样进入更多，不在操作栏重复排列。导航与局部上下文入口可同时保留，但必须确有使用价值。资料管理不设置任务中心按钮，工具页面可保留局部任务入口。

字体栈：微软雅黑 → 苹方 → Noto Sans CJK SC → Arial → 系统无衬线字体。中文正文不使用细字重或人为拉大字距；英文装饰性副标题不能挤压业务名称。

长文件名在列表中可省略，必须能通过悬停、键盘焦点或详情获取完整名称；原文、关键错误、金额单位和必须阅读的配置要求不能仅以省略号显示。

层级统一为：正文 → 吸顶表头 → 导航 → 下拉菜单 → 弹窗 → 即时反馈。浮层必须显示在裁切区域外，不能被表格或卡片截断；实现可沿用现有分层值，不要求为文档新增一套框架。

5. 全局布局与空间优先级

5.1 页面骨架

区域 职责 稳定规则
左侧全局菜单 在资料、任务、模板和工具间导航 可折叠、可展开；保留图标与当前项，偏好可记忆
页头 / 工具命令栏 告知当前位置，完成页面主任务 单行、紧凑；不放长介绍、欢迎区或重复导航
左侧资料区 组织目录或本次资料 支持独立滚动，不挤压正文；必要时收起
中间工作区 资料列表、预览、结果与来源 默认取得主要剩余空间；结果完成后聚焦结果
右侧辅助区 工具入口或本次配置 可收起、可恢复；技术参数按需展开

资料管理取消独立页头与位置行，当前位置、文件名搜索、上传下拉与更多合并为约58px的一条操作栏。文本检索放在更多第一项；已选数量与取消选择并入既有分页栏，文件列表排序移除，左侧目录拖动保留，不新增状态或排序行。工具页面命令栏以56px为桌面基线，低矮桌面窗口可为50px，手机宽度保持54px单行。数字用于统一组件，不能为了严格卡高度而裁切文字。

UI-07：内容多时让工作区滚动，不让页头不断长高。 表格表头、必要的主操作和弹窗底部操作保持可达。避免整页、表格、卡片同时形成方向相同且难辨认的多层滚动。

5.2 响应式与操作收纳

资料工具栏按中间资料区实际可用宽度适配，不能只判断浏览器宽度；菜单折叠、目录拉宽、工具区收起都应重新计算。

资料区可用宽度 主工具栏 收纳位置
≥900px 当前路径 → 名称搜索 → 范围 → 筛选 → 上传 → 更多 文本检索位于更多第一项
720–899px 当前路径 → 名称搜索 → 筛选 → 上传 → 更多 浏览范围进入筛选面板；文本检索在更多
<720px 当前路径 → 名称搜索 → 上传 → 更多 范围、状态、类型筛选和文本检索进入更多

UI-08：移动入口，不丢配置。 收纳前后必须保留输入值、筛选、勾选、当前目录和任务；同一筛选字段只有一个有效实例。菜单中筛选已生效时，主入口须有状态提示，不能让用户误以为数据缺失。

UI-22：空间顺序固定为“公共空间 → 项目空间 → 个人空间”。 资料管理、添加资料、移动文件、上传记录筛选和本次资料分组统一采用该顺序；仅调整排列，不重置用户当前空间或更改资料归属。

表格允许内部横向滚动；不能造成整页横向溢出。窄屏可以隐藏次要元数据，但必须在详情中保留。文件名、关键状态和操作入口优先保留；金额、日期、单位等结果字段按具体审计任务确定优先级，不能机械隐藏。

6. 按钮、链接与“更多”

6.1 按钮层级

类型 外观 使用情形 不应这样使用
主按钮 实心主色 上传资料、执行分析、确认提交 同一任务区并列多个争抢注意力的主按钮
次按钮 中性边框 添加资料、导出、取消等辅助动作 为了醒目给所有按钮加重描边
强辅助按钮 浅主色 文本检索等高频入口 与最终提交混淆
文字链接 无大背景 打开、编辑、查看来源、取消选择 用模糊文字触发删除等高风险操作
图标按钮 小画布、合理点击区 下载、附件、行内省略号 用雷同图标表示不相干动作，或只在鼠标悬停后才可发现
危险操作 红色文字，放低优先级位置 删除、撤销授权 作为页面主色大按钮常驻

UI-09：动词必须带清楚的作用对象。 页面级“上传资料”、菜单内“移动所选资料”、行内“管理文件夹”，以及“取消选择”和“删除资料”含义不能混用。

6.2 更多菜单与行内省略号

独立的“按什么排序”状态行不保留。已选数量和取消选择放在现有分页栏；文件列表排序按最新要求移除，左侧目录同级拖动保留。

“更多”用于承载低频操作及空间不足时收纳的辅助操作，不是删除功能的理由，也不是把核心入口藏起来的理由。按 Ant Design Dropdown 的下拉组织方式，以及 IBM Carbon 表格规范 对表格、批量、行内操作的区分建立稳定分组。

资料管理菜单固定分组：

分组 内容 规则
检索与记录 文本检索、上传记录 文本检索在首项，上传记录不重复
查找与筛选 浏览范围、文档状态、文件类型、重置 仅在窄宽度下承接原筛选控件；不重复放文本检索
所选资料 移动、重新解析、删除 显示所选数量；没有适用对象时禁用并说明原因
目录与视图 目录权限与说明、分析工具显隐 不与批量文件操作混在同一无标题列表中

UI-10：低频目录管理使用轻量省略号。 圆点使用实心填充图形（fill=currentColor、stroke=none），不得使用空心圆圈或近零长度短线；图形必须实际可辨认，默认可见、颜色清楚；悬停和键盘焦点增强反馈，提示中包含目录名称。不得恢复成“管理”大按钮，不得通过极低透明度隐藏。

文件夹行使用“打开 + 省略号”；文件行使用“文件名打开原文 + 下载 + 附件 + 省略号”。窄屏收纳下载和附件时，详情必须保留对应操作。省略号只管理当前行，顶部“更多”中的批量项只处理勾选范围。

菜单点击打开，点击外部或 Esc 关闭，方向键可进入，关闭后焦点返回触发器。菜单限高、内部滚动，不越屏、不被卡片裁切。禁用项要有可读原因，不能让键盘用户只能依靠不可聚焦的禁用按钮读取提示。

7. 表格、选择范围与数据密度

UI-11：表格列服务当前任务。 资料列表固定名称、文档状态、所有者、位置、上传时间和操作；大小、最近查看等完整信息放详情。保留既有决定，不新增“设置显示列”。位置列显示空间与文件夹完整路径，窄屏仍保留，长路径省略并提供完整提示；必要业务列在表格内部横向滚动。工具的本次资料清单在窄工作区可将位置并入文件名下方，必须明确标注“位置”，不能与资料管理固定列规则混淆。其他工具结果表按审计判断所需设计列，不能照搬资料表。

规则 具体要求
行高 资料表以约 60–68px 容纳文件名及一行辅助信息；结果表单行以 44–48px 为建议起点，允许内容自然增高
对齐 文件名和正文左对齐；金额等数值右对齐；单位放列名或值旁；同列精度一致
表头 明确、可读、必要时吸顶；资料列表无排序控件；其他业务结果确需排序时明确方向与范围
文件与文件夹 同一层可同时出现；目录优先排列；文件夹不能被误计为已选文件
当前页与全部 文案明确区分“本页”“所有页/全部结果”；总数来自真实范围，不把当前加载量当全量
跨页和跨目录 已选范围保留，可点击数量核对；筛选不静默清除勾选
选择反馈 勾选、部分选中、全选状态一致；取消选择不删除数据
批量动作 对象数量、权限和适用状态明确；只处理当前已选范围
无结果 显示“没有符合条件的资料”并可清除筛选，不能与空目录混为一谈

资料选择弹窗沿用资料管理的“本页/全部页”选择规则：全部页遵循当前目录、名称与子文件夹范围，文件夹不计为文件；明确半选、其他范围已选，并允许仅保留本页或取消本范围。分页和确认操作保持可达，取消不改原资料，选表仍为单选。

行内仅点击名称或明确入口打开内容，不把整行点击、勾选、双击、拖动混为同一个动作。复制字段、打开原文等行为不得改变本次分析范围。

8. 目录树、文件组织与拖动

UI-12：文件夹层级、当前目录和资料归属必须一致。 目录树负责定位，列表展示当前目录；当前位置使用可返回上级的路径，不恢复嵌入框架的全局面包屑栏，当前选中项清楚。长名称通过省略和详情处理，不能无限加宽目录挤压工作区。

11.1 任务中心的业务表达

任务中心跟踪各工具AI分析及结果，不与上传/OCR记录混淆。紧凑标题与过滤栏，固定分类、表头和分页，表格内部滚动。过滤支持名称/备注、工具、状态，低频日期/任务类型进入筛选。列表固定任务名称、工具/范围、分析状态/进度、结果及后续操作、创建时间和操作。正文16px，辅助14px，1024×480保留核心列表。

“查看结果”进入对应工具专属工作区；任务信息单独展示进度原因、资料范围与只读配置。行内三点收纳任务信息、备注、终止/删除记录，主结果入口不折叠。返回任务中心保留当前过滤、页码、勾选与滚动。未知业务类型只显示任务信息，不能猜测打开另一工具；招投标与待摊费用虽共享type10，必须依业务类型区分。

结果摘要使用各工具实际返回的业务单位：提取资料/字段、词语/词次、会议/议题、主题/基础信息、事项/日期未知、检查项/线索、项目关系/关联候选、计费约定/费用。文件分析数量与结果行数、风险数量不同，不相互推算。“分析完成”指AI返回结果，不代表审计问题已确认，不新增未经后台支持的人工审核状态。

排队、运行、部分完成、失败、待填写基数、已终止分别表达。进度已知才显示百分比，未知显示待更新；阶段进度与整体进度不能混用。主题归纳失败保留基础信息，只重试归纳阶段；待摊费用第一阶段完成引导填写基数。终止保留已返回结果，删除记录不删除原资料；原失败重试能力继续从对应工具使用。

合并导出支持同一工具至少两项任务跨页勾选，字段不同时取并集，不限制为信息提取或字段完全相同。保留Excel/SQL、三用途及中英字段映射、分文件、有效期、独立导出任务和ZIP下载。运行中任务提交前提示等待完成；部分完成仅导出已有结果，明确遗漏范围。合并/提交/下载均核对权限，原分析快照保留。正式后台链接刷新、重试和30天文件保留仍沿用原服务能力。

12. 结果核验、原文与导出

UI-17：审计结果必须可解释、可追溯。 结果项尽量提供源文件、对应章节/页码/源行、原文内容和关联资料；位置未获得真实依据时，不伪造页码或精确定位。

核验入口应返回原结果上下文，保留筛选、选中项和滚动位置。快速切换原文时，迟到请求不能覆盖当前文件；无原文、解析未完成、下载失效分别说明并给恢复路径。

正文检索与名称搜索分开。多处命中可逐个定位，关键词高亮同时保留上下文；修改检索词后，明确旧结果需要重新执行。清空检索条件与清空资料范围分开。

导出前明确格式、对象和范围，使用完整结果或完整正文的入口不能只导出屏幕可见部分。导出时重查权限，部分失败说明遗漏项。开始新分析不能覆盖旧任务结果；引用、附件与源文件之间的关系保持可追溯。

13. 权限与敏感操作的界面表达

UI-18：查看、使用、修改和分配权限分别判断。 不把“能查看”当成“能修改”，不把“能管理资料”当成“能分配权限”，也不把项目根节点“不能直接上传”误标为整个目录只读。

项目、个人、公共空间遵守原有不同规则；引用目录、归档同步目录及系统结构节点不能通过统一 UI 被意外放开。文件上传者等原有例外按源码和后台规则保留，不以“统一风格”删除能力。

常态页头不堆放“项目目录”“查看权限”等标签。资料管理“当前位置”后不显示锁图标；只读等实际限制在相关操作和“目录权限与说明”中以文字说明，不能仅依赖悬停。移除装饰图标不改变权限判断。

未获授权的入口按原规则隐藏或禁用；禁用要能解释原因。打开页面时和提交时都检查权限，权限变化后刷新可用能力；前端隐藏不构成授权，生产授权由后台落实。
