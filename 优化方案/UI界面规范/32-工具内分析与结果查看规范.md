# 工具内分析与结果查看规范

更新日期：2026-10-24。适用于全部 11 项工具；与早期“执行后前往任务中心”的说明冲突时，以本规范为准。

## 常规使用流程

添加资料 → 设置分析内容 → 开始分析 → 当前页查看进度 → 当前页查看结果。任务中心保留跨工具集中跟踪、查找与导出功能，查看成果不以进入任务中心为前提。

1. 从导航打开工具，仍进入本工具的准备页，避免误把历史任务当成新分析。准备页右上提供“分析记录”，仅列当前工具的记录。
2. 提交分析后默认留在当前工具。运行时显示进度；完成后呈现该工具自己的成果，不统一替换成通用表格。
3. 离开后，可通过本工具“分析记录”重新打开结果或进度。记录支持名称、备注查找、状态筛选及分页，不沿用任务中心的筛选条件；打开时自动更新任务状态，保留查找输入、焦点与列表滚动位置。
4. 结果页保留“调整后再分析”“导出”；紧凑的本次分析名称行提供“分析记录”。不增加常驻资料清单，也不挤占主要结果空间。
5. 调整后再分析进入独立草稿，确认后新建任务；原记录及已返回结果保持。查看配置或导出页面中的“分析结果”返回同一任务结果。

## 不同任务状态

| 状态 | 记录中的操作 | 当前工具内的行为 |
| --- | --- | --- |
| 排队、运行中 | 查看进度 | 排队明确等待，不显示虚构进度或完成结果；保留原终止确认流程 |
| 已完成 | 查看结果 | 展示对应工具的实际业务成果 |
| 部分完成 | 查看已完成结果 | 保留已有结果及原失败项处理能力 |
| 失败 | 查看失败原因 | 展示服务返回的具体原因，未返回时明确说明，沿用原重试流程 |
| 已停止 | 查看已停止任务 | 可调整后再分析，不直接重新启动已停止的历史记录 |
| 费用待续算 | 继续计算 | 填写基数后在同一任务中继续生成费用报告 |

主题归纳的后续阶段、会议风险分析与问答、费用计算等原阶段逻辑均保留。不能因统一入口而丢失业务步骤。

## 执行方式与页面去向

- “立即执行 / 排队执行”沿用原 `task_switch=1/2`，描述任务执行方式。
- “提交后前往任务中心”是独立选项，默认不勾选，收在“执行设置”。选择排队执行不会自动勾选页面跳转。
- 仅在成功创建任务后应用跳转；校验失败、空名称或取消不创建任务，也不切换页面。
- 历史记录中的执行方式读取实际快照；未记录时显示“未记录”，不推断为立即执行。

## 统一样式与边界

正文与主要控件 16px，辅助说明不低于 14px。记录列表独立滚动，表头固定，分页及关闭按钮可达；窄屏表格横向滚动，不把整个页面撑宽。

不增加后端接口。工具分类沿用业务解析，不能只依赖数字任务类型，因为招投标与旧费用任务可能共用类型 10。原资料权限、结果来源、导出及任务状态能力继续由既有处理函数承接。

浏览器原型中的任务为本地演示；页面关闭后的实际运行、服务端排队和轮询仍按正式接口联调，不把本地计时器当成真实后台服务。

## 验收证据

`tests/browser_in_tool_records.py` 覆盖 11 工具记录隔离、只读历史、检索分页、排队终止、费用同任务续算、三类提交、执行方式保留、独立跳转、取消与空名称、配置和导出页返回；在 1366×768、1024×480、390×600 检查列表与页脚。结果和历史复用另由各工具专项回归覆盖。
