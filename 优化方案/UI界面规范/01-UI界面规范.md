# 审计文档挖掘助手 · UI 界面规范

版本：1.3　｜　核对日期：2026-10-19　｜　用途：产品评审、界面设计、前端实施与验收

**总原则：高频任务直达，低频功能收纳；文字清楚、操作常规，把主要空间留给资料和审计结果。**

## 1. 适用范围与使用顺序

适用于资料管理、任务中心、提取模板及全部 11 项分析工具，包括添加资料、配置、运行、结果、原文核验、导出和权限相关界面。覆盖桌面及窄屏使用；屏幕界面的字号、布局与导出公文的排版分别管理。

本规范已合并08–15号补充中的有效规则，作为本轮统一基线。执行顺序：用户最新明确要求 → 本主规范及设计变量/验收清单 → 各工具业务核对说明。08–15号文档保留追溯，不再作为互相竞争的独立规范；旧PDF与截图仅代表其历史版本。功能和权限以核对过的原系统能力及后台授权为准。

文中的“必须”是验收要求，“建议”是默认设计值。规范要求与现有实现完成度分开记录，不以发布规范代替逐页验收。当前已验证范围及待整改项见第 17 节。

配套文件：[验收清单](02-界面验收清单.md)、[设计变量](03-设计变量.json)、[可视化阅读版](04-UI规范阅读版.html)、[图标规范](05-图标规范与图标表.md)、[图标速查](06-图标速查.html)。

## 2. 信息与操作的优先级

| 层级 | 判断依据 | 展示方式 | 本系统中的应用 |
| --- | --- | --- | --- |
| 核心任务 | 当前页面要完成的主要目标 | 明确的主按钮、主要内容区 | 上传、开始提取/开始分析、查看结果 |
| 高频辅助 | 经常使用、影响任务效率 | 直接可见的次按钮或搜索框 | 添加资料、名称搜索、当前结果筛选 |
| 按需使用 | 不应持续占用核心区域 | 更多菜单、行内省略号、详情 | 文本检索、上传记录、移动、重新解析、目录管理 |
| 背景说明 | 解释结构或能力，通常无需立即判断 | 详情、提示、按需展开 | 项目目录类型、完整权限说明、高级参数 |
| 异常状态 | 影响当前操作，需要立即知晓 | 简短状态、局部提示与恢复入口 | 只读、解析失败、缺少原文、部分失败 |

**UI-01：每个独立任务区域原则上只有一个实心主按钮。** 不把所有功能做成同等大小、同等颜色的按钮；页面级操作、所选资料操作、单行操作必须分清对象。

**UI-02：操作栏空间不足时，优先收纳，不能以缩小文字或增加按钮行数换取容纳量。** 表单字段、说明文字和正文可以正常换行；主命令栏与资料工具栏保持单行。极窄屏下保留任务主入口，其余进入菜单。

**UI-03：同一区域不重复提供相同操作。** 资料管理的文本检索仅在“更多”第一项；上传记录同样进入更多，不在操作栏重复排列。导航与局部上下文入口可同时保留，但必须确有使用价值。资料管理不设置任务中心按钮，工具页面可保留局部任务入口。

## 3. 字体、文字层级与可读性

### 3.1 字号基线

| 文字角色 | 字号 | 字重 | 行高 | 适用位置 |
| --- | --- | --- | --- | --- |
| 独立页面标题 | 22px；允许20–24px | 600–650 | 1.4 | 任务中心等确需独立标题的页面；资料管理和提取模板不增加标题行 |
| 工具名称 | 18px | 600 | 1.4 | 一行紧凑业务操作栏 |
| 弹窗标题 | 20px | 600 | 1.4–1.5 | 编辑、上传、核验弹窗 |
| 区块标题 | 普通内容18px；密集面板16px | 600 | 1.5 | 本次资料、配置面板、结果分组 |
| 正文及主要操作 | 16px | 400；强调 500–600 | 1.5–1.6 | 导航、文件名、配置字段、输入框、主要按钮 |
| 辅助信息 | 14px，下限 14px | 400–500 | 1.6 | 表头、时间、大小、状态、路径说明、选择概况 |
| 原文阅读 | 16px | 400 | 1.8–1.9 | 文档正文、检索上下文、核验内容 |

字体栈：微软雅黑 → 苹方 → Noto Sans CJK SC → Arial → 系统无衬线字体。中文正文不使用细字重或人为拉大字距；英文装饰性副标题不能挤压业务名称。

**UI-04：所有业务可见文字不低于 14px，低分辨率规则不得覆盖成 9–12px。** 不通过整体缩放、压缩行高或截图文字代替真实文本。状态栏中的辅助链接可使用 14px，但正文操作和表单保持 16px。

长文件名在列表中可省略，必须能通过悬停、键盘焦点或详情获取完整名称；原文、关键错误、金额单位和必须阅读的配置要求不能仅以省略号显示。

### 3.2 颜色与对比度

| 语义 | 规范色值 | 使用规则 |
| --- | --- | --- |
| 页面背景 | `#F4F6F9` | 承托内容，避免大面积高饱和装饰 |
| 内容背景 | `#FFFFFF` | 表格、原文、配置和弹窗 |
| 主文字 | `#1E3046` | 正文、重要标题 |
| 次文字 | `#596B80` | 可读的辅助信息，不能再随意调浅 |
| 表头文字 / 背景 | `#52657B` / `#F5F7FA` | 结构清楚，表头不能比正文更难辨认 |
| 主色 / 主色浅背景 | `#3269DB` / `#EEF4FF` | 主要行动、选中、链接；不用于装饰全部组件 |
| 主色悬停 | `#2458C2` | 主操作的悬停反馈 |
| 分割线 / 控件边框 | `#E6EBF1` / `#DCE3ED` | 分隔区域；需要辨识的控件不能只依赖极浅线条 |
| 侧栏背景 | `#172C40` | 导航；文字与图标须在深色背景上保持可读 |
| 成功文字 / 背景 | `#1D735B` / `#EAF7F2` | 已完成、保存成功；不代表审计结论已确认 |
| 警示文字 / 背景 | `#8A5A16` / `#FFF5E5` | 待处理、缺少资料、需要补充 |
| 失败文字 / 背景 | `#A33E3E` / `#FCEEEE` | 操作失败、解析异常 |
| 危险操作文字 | `#B34848` | 删除、撤销授权等；配合明确动词和确认 |

成功、警示、失败三组文字色已应用到共用状态标签；实际计算样式与整改记录见第17节。该结论不扩展到任意自定义图表和上传原件。

**UI-05：普通文本与背景的对比度至少 4.5:1。** 本项目统一以这一值验收常见的 14–22px 文字，不把“标题加粗”当作默认放宽条件；状态不能仅凭颜色区分。该要求参考 [W3C WCAG 2.2：文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

## 4. 间距、尺寸、形状与动效

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 基础间距 | 4 / 8 / 12 / 16 / 24 / 32px | 新增组件优先使用这组值；既有 9–10px 紧凑内距可按组件保留 |
| 同组控件间距 | 8px | 密集行内图标可为 4px，但点击区域不能重叠 |
| 内容区间距 | 12–16px | 依任务区分层，不靠大块空白制造层次 |
| 表单组间距 | 16–24px | 标签与控件 6–8px；错误就近显示 |
| 常规文字按钮 / 输入框 | 高度至少 36px | 视觉高度与点击区域一致，文字不裁切 |
| 行内图标点击区 | 默认 30×32px | 目录树可为 25×28px；小图标不等于小点击区 |
| 图标画布 | 18–20px；辅助图标可为 16px | 线宽约 1.6–1.8px，必须有清晰的实际笔画 |
| 圆角 | 轻量操作 4px、控件 8px、面板 9px、弹窗 10px | 同一组件不可随页面任意变化 |
| 边框 | 1px | 轻量省略号默认无边框，不做成大管理按钮 |
| 动效 | 120–180ms；复杂展开不超过 200ms | 反馈服务于定位；支持减少动画设置 |

**UI-06：图标可小而清楚，点击区必须足够。** 本项目要求独立操作目标至少能容纳 24×24 CSS px，主要按钮使用 36px 高度；触屏可扩大透明点击区而不扩大视觉按钮。24px 基准参考 [W3C WCAG 2.2：目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)，不能把图标画布大小当作目标大小。

层级统一为：正文 → 吸顶表头 → 导航 → 下拉菜单 → 弹窗 → 即时反馈。浮层必须显示在裁切区域外，不能被表格或卡片截断；实现可沿用现有分层值，不要求为文档新增一套框架。

## 5. 全局布局与空间优先级

### 5.1 页面骨架

| 区域 | 职责 | 稳定规则 |
| --- | --- | --- |
| 左侧全局菜单 | 在资料、任务、模板和工具间导航 | 可折叠、可展开；保留图标与当前项，偏好可记忆 |
| 页头 / 工具命令栏 | 告知当前位置，完成页面主任务 | 单行、紧凑；不放长介绍、欢迎区或重复导航 |
| 左侧资料区 | 组织目录或本次资料 | 支持独立滚动，不挤压正文；必要时收起 |
| 中间工作区 | 资料列表、预览、结果与来源 | 默认取得主要剩余空间；结果完成后聚焦结果 |
| 右侧辅助区 | 工具入口或本次配置 | 可收起、可恢复；技术参数按需展开 |

资料管理取消独立页头与位置行，当前位置、文件名搜索、上传下拉与更多合并为约58px的一条操作栏。文本检索放在更多第一项；已选数量与取消选择并入既有分页栏，文件列表排序移除，左侧目录拖动保留，不新增状态或排序行。工具页面命令栏以56px为桌面基线，低矮桌面窗口可为50px，手机宽度保持54px单行。数字用于统一组件，不能为了严格卡高度而裁切文字。

**UI-07：内容多时让工作区滚动，不让页头不断长高。** 表格表头、必要的主操作和弹窗底部操作保持可达。避免整页、表格、卡片同时形成方向相同且难辨认的多层滚动。

### 5.2 响应式与操作收纳

资料工具栏按**中间资料区实际可用宽度**适配，不能只判断浏览器宽度；菜单折叠、目录拉宽、工具区收起都应重新计算。

| 资料区可用宽度 | 主工具栏 | 收纳位置 |
| --- | --- | --- |
| ≥900px | 当前路径 → 名称搜索 → 范围 → 筛选 → 上传 → 更多 | 文本检索位于更多第一项 |
| 720–899px | 当前路径 → 名称搜索 → 筛选 → 上传 → 更多 | 浏览范围进入筛选面板；文本检索在更多 |
| <720px | 当前路径 → 名称搜索 → 上传 → 更多 | 范围、状态、类型筛选和文本检索进入更多 |

**UI-08：移动入口，不丢配置。** 收纳前后必须保留输入值、筛选、勾选、当前目录和任务；同一筛选字段只有一个有效实例。菜单中筛选已生效时，主入口须有状态提示，不能让用户误以为数据缺失。

**UI-22：空间顺序固定为“公共空间 → 项目空间 → 个人空间”。** 资料管理、添加资料、移动文件、上传记录筛选和本次资料分组统一采用该顺序；仅调整排列，不重置用户当前空间或更改资料归属。

表格允许内部横向滚动；不能造成整页横向溢出。窄屏可以隐藏次要元数据，但必须在详情中保留。文件名、关键状态和操作入口优先保留；金额、日期、单位等结果字段按具体审计任务确定优先级，不能机械隐藏。

## 6. 按钮、链接与“更多”

### 6.1 按钮层级

| 类型 | 外观 | 使用情形 | 不应这样使用 |
| --- | --- | --- | --- |
| 主按钮 | 实心主色 | 上传资料、执行分析、确认提交 | 同一任务区并列多个争抢注意力的主按钮 |
| 次按钮 | 中性边框 | 添加资料、导出、取消等辅助动作 | 为了醒目给所有按钮加重描边 |
| 强辅助按钮 | 浅主色 | 文本检索等高频入口 | 与最终提交混淆 |
| 文字链接 | 无大背景 | 打开、编辑、查看来源、取消选择 | 用模糊文字触发删除等高风险操作 |
| 图标按钮 | 小画布、合理点击区 | 下载、附件、行内省略号 | 用雷同图标表示不相干动作，或只在鼠标悬停后才可发现 |
| 危险操作 | 红色文字，放低优先级位置 | 删除、撤销授权 | 作为页面主色大按钮常驻 |

**UI-09：动词必须带清楚的作用对象。** 页面级“上传资料”、菜单内“移动所选资料”、行内“管理文件夹”，以及“取消选择”和“删除资料”含义不能混用。

### 6.2 更多菜单与行内省略号

独立的“按什么排序”状态行不保留。已选数量和取消选择放在现有分页栏；文件列表排序按最新要求移除，左侧目录同级拖动保留。

“更多”用于承载低频操作及空间不足时收纳的辅助操作，不是删除功能的理由，也不是把核心入口藏起来的理由。按 [Ant Design Dropdown](https://ant.design/components/dropdown/) 的下拉组织方式，以及 [IBM Carbon 表格规范](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) 对表格、批量、行内操作的区分建立稳定分组。

资料管理菜单固定分组：

| 分组 | 内容 | 规则 |
| --- | --- | --- |
| 检索与记录 | 文本检索、上传记录 | 文本检索在首项，上传记录不重复 |
| 查找与筛选 | 浏览范围、文档状态、文件类型、重置 | 仅在窄宽度下承接原筛选控件；不重复放文本检索 |
| 所选资料 | 移动、重新解析、删除 | 显示所选数量；没有适用对象时禁用并说明原因 |
| 目录与视图 | 目录权限与说明、分析工具显隐 | 不与批量文件操作混在同一无标题列表中 |

**UI-10：低频目录管理使用轻量省略号。** 圆点使用实心填充图形（fill=currentColor、stroke=none），不得使用空心圆圈或近零长度短线；图形必须实际可辨认，默认可见、颜色清楚；悬停和键盘焦点增强反馈，提示中包含目录名称。不得恢复成“管理”大按钮，不得通过极低透明度隐藏。

文件夹行使用“打开 + 省略号”；文件行使用“文件名打开原文 + 下载 + 附件 + 省略号”。窄屏收纳下载和附件时，详情必须保留对应操作。省略号只管理当前行，顶部“更多”中的批量项只处理勾选范围。

菜单点击打开，点击外部或 Esc 关闭，方向键可进入，关闭后焦点返回触发器。菜单限高、内部滚动，不越屏、不被卡片裁切。禁用项要有可读原因，不能让键盘用户只能依靠不可聚焦的禁用按钮读取提示。

## 7. 表格、选择范围与数据密度

**UI-11：表格列服务当前任务。** 资料列表固定名称、文档状态、所有者、位置、上传时间和操作；大小、最近查看等完整信息放详情。保留既有决定，不新增“设置显示列”。位置列显示空间与文件夹完整路径，窄屏仍保留，长路径省略并提供完整提示；必要业务列在表格内部横向滚动。工具的本次资料清单在窄工作区可将位置并入文件名下方，必须明确标注“位置”，不能与资料管理固定列规则混淆。其他工具结果表按审计判断所需设计列，不能照搬资料表。

| 规则 | 具体要求 |
| --- | --- |
| 行高 | 资料表以约 60–68px 容纳文件名及一行辅助信息；结果表单行以 44–48px 为建议起点，允许内容自然增高 |
| 对齐 | 文件名和正文左对齐；金额等数值右对齐；单位放列名或值旁；同列精度一致 |
| 表头 | 明确、可读、必要时吸顶；资料列表无排序控件；其他业务结果确需排序时明确方向与范围 |
| 文件与文件夹 | 同一层可同时出现；目录优先排列；文件夹不能被误计为已选文件 |
| 当前页与全部 | 文案明确区分“本页”“所有页/全部结果”；总数来自真实范围，不把当前加载量当全量 |
| 跨页和跨目录 | 已选范围保留，可点击数量核对；筛选不静默清除勾选 |
| 选择反馈 | 勾选、部分选中、全选状态一致；取消选择不删除数据 |
| 批量动作 | 对象数量、权限和适用状态明确；只处理当前已选范围 |
| 无结果 | 显示“没有符合条件的资料”并可清除筛选，不能与空目录混为一谈 |

资料选择弹窗沿用资料管理的“本页/全部页”选择规则：全部页遵循当前目录、名称与子文件夹范围，文件夹不计为文件；明确半选、其他范围已选，并允许仅保留本页或取消本范围。分页和确认操作保持可达，取消不改原资料，选表仍为单选。

行内仅点击名称或明确入口打开内容，不把整行点击、勾选、双击、拖动混为同一个动作。复制字段、打开原文等行为不得改变本次分析范围。

## 8. 目录树、文件组织与拖动

**UI-12：文件夹层级、当前目录和资料归属必须一致。** 目录树负责定位，列表展示当前目录；当前位置使用可返回上级的路径，不恢复嵌入框架的全局面包屑栏，当前选中项清楚。长名称通过省略和详情处理，不能无限加宽目录挤压工作区。

目录管理入口在目录树和列表行中保持同一权限及行为。新建文件夹仅通过有权限的目录省略号菜单创建下级；空间根级确需创建时使用空间管理菜单。不保留左目录底部常驻“新建文件夹”，右上也不重复设置。

拖动排序严格保留原系统范围：

| 项目 | 规则 |
| --- | --- |
| 角色与空间 | 超级文件管理员；个人空间、公共空间 |
| 可排序对象 | 同一父目录下的文件夹，不含空间根节点 |
| 拖动反馈 | 六点手柄与前/后插入线；不能显示可放入子级的错误暗示 |
| 禁止行为 | 跨父目录、跨空间、拖入目录或改变层级；项目空间不扩展未支持的排序保存能力 |
| 保存后 | 文件路径、资料关联、当前目录、勾选与展开状态保持；刷新后顺序可恢复 |
| 替代操作 | 保留菜单同级上移/下移、手柄键盘操作 |

**UI-13：拖动排序与“移动文件夹”是不同功能。** 前者只改显示顺序；后者改变父级，使用独立入口与确认。生产接入继续沿用既有排序接口，提交完整同级后台 ID，不用显示名称或路径冒充 ID。

上传文件夹沿用原流程：选择目录 → 同名目录合并提示 → 类型筛选 → 重名处理 → 上传解析。类型可勾选，默认排除压缩、可执行、临时和系统文件，支持仅创建目录。保留原路径、多级目录及同层文件，按完整相对路径判重；提交前重查子目录与覆盖权限。目录API或拖入的目录条目可保留空子目录，兼容输入框未返回的空目录不能伪造。正式接入沿用原接口、100MB上限、上传会话和分片恢复逻辑。

嵌入框架时以子页面可用视口为准。资料区域必须设置可收缩的最小高度、独立滚动和稳定分页，不能因表格默认最小高度把页面撑出屏幕；窄屏分析工具按需侧向展开，不挤占资料高度。

目录查找和表单中文输入遵守输入法组合生命周期：候选编辑期间不得重建输入节点或执行查询/提交，选词完成后更新一次；回车选词不等同于回车提交。资料管理、资料选择和工具目录保持同一规则。

## 9. 表单、配置、提示词与模板

**UI-14：默认配置与误操作风险匹配，扩展能力按需展开。** 常见审计任务可提供默认方案；信息提取的新配置默认不选模板、不预填字段，用户明确选模板或自行添加字段后才能开始。已编辑草稿和历史任务不自动清空。用户能修改本次要求，并保存可复用的个人模板。高级参数不与“执行分析”争夺首屏空间。

| 组件 | 规范 |
| --- | --- |
| 标签 | 标签常驻，不以 placeholder 代替；必填、单位、作用范围明确 |
| 输入框 | 16px，至少 36px 高；有值、清空、禁用、校验错误状态完整 |
| 下拉框 | 显示当前选择；选项不被容器裁切；搜索选项和自由输入能力按实际业务提供 |
| 长文本 | 提示词、审计关注点可展开或进入编辑器，保留输入，不在窄列里强行完整铺开 |
| 校验 | 在字段附近说明问题和修正方法；提交时定位到首个无效字段；不能只弹“参数错误” |
| 高级参数 | 用业务能理解的名称、默认值和解释；纯后台信息放诊断详情，不进入正常操作流程 |
| 单位 | 金额、比例、阈值单位明确；空值不自动当作 0；切换单位不静默改变含义 |

提取模板定位于信息提取的字段定义；其他工具的提示词和分析方案在各自配置区管理，不能把全部方案混入提取模板。系统模板按权限只读，允许复制为个人模板；“修改本次要求”“另存个人副本”“管理提取模板”是三个不同动作。取消编辑不污染原模板，保存与未保存状态清楚；切换方案影响已有字段时说明影响。

提示词、字段、检查项、停用词、用户新词、归类规则、阈值和权重等，按现有工具能力可配置。配置入口、名称与版本/快照信息统一；未来新增工具通过共用结构接入，不把可变化的业务规则写死在页面布局中。

## 10. 分析工具的统一操作路径

**UI-15：统一为“本次资料 → 本次配置 → 执行分析 → 核验结果 → 导出”。** 左侧资料、右侧配置、中间内容的职责保持稳定；执行按钮位于工具命令栏右侧。“添加资料”在准备、历史结果、宽屏结果和运行相关场景中保持可达，并按原规则处理新分析与历史任务。

信息提取默认入口进入准备页，采用“Step 1 添加资料—Step 2 核对原文—Step 3 配置提取字段”三栏。默认入口与历史任务结果区分，不能因上次看过结果而收起配置区；历史使用明确任务地址，刷新和前进/后退保持对应任务，未提交草稿单独保留。左右资料/字段栏等宽（桌面各368px，1200px以内各320px），中间原文弹性。左侧仅保留逐份移除，不再提供批量移除；点击文件只切换预览，移除不删除资料库原件。每份文件旁仅提供附件、移除两个图标（32px点击区、18px图标），悬停与无障碍名称明确含义，已有附件使用浅蓝底提示；历史任务仅查看关联快照。准备页不重复显示“解析完成”，文件名单行截断并悬停展示全名，以约42px紧凑行承载大量文件，异常或执行状态仍可说明。Step 1标题与添加资料按钮合为一行，不另设重复添加按钮行。提示只说明“可跨目录选择，仅添加解析完成的资料”，不把核对原文、关联附件暗示为必做步骤；底部统一说明全部已选资料参与提取。右侧不再重复提供提取模板管理超链接，管理从系统菜单进入；“另存为个人模板”位于模板选择区的次要操作，字段区只保留带加号的标准“添加字段”按钮；字段为空时保存和开始均禁用，显示如何选择模板或添加字段。另存只填写名称、个人分类与描述，完整保存当前字段及口径，不覆盖原模板。中间默认打开真实原始文件，支持切换解析内容和放大对照；右侧直接编辑字段名称和提取说明，输入时不重载原件。修改即时保存为本次副本，列表全部字段参与提取；模板替换前确认，历史配置只读。模板导入、导出和删除统一进入独立提取模板管理，工具中不重复设置管理菜单。附件合并、分段参数放入“附件与提取设置”；关联附件窗口同时提供“提取时包含附件内容”开关，明示影响本次全部资料，未开启时仅提取主文件。原文区标题、文件名、翻页各保留紧凑单行，路径可悬停查看。添加资料弹窗去掉与现有选择重叠的“加入目录”，通过本级/含子文件夹和本页/全部页明确范围。选择资料只允许解析完成且有提取权限的文件，禁选状态保留可见并解释原因；本页、全部页及确认时统一重查。附件选择按原源码仅从已添加文件和已打开文件夹列表取候选，排除自身和已关联项；多选、搜索、取消暂存、确认追加均可操作，不覆盖原关联或改变主文件范围。工具附件关联独立于目录编辑权限，明确禁止关联、无提取权限或历史任务均只读；不提升目录权限。900px以内通过资料/原文/字段面板切换适配，1024×480保留原文与字段独立滚动，不缩小字号。

预览文件不改变执行范围；按钮附近可查看将处理的资料数量。未解析、不支持格式、无查看权限的文件必须解释处理方式，不能静默漏掉。已有任务引用和配置快照不随新编辑被覆盖。

| 工具 | 需要保留的特有能力 | 结果表达重点 |
| --- | --- | --- |
| 信息提取 | 模板、字段编辑、字段校验、附件合并 | 字段表与来源原文，缺失值可辨认 |
| 词云分析 | 展示词数、停用词、专有词 | 词云与词频表联动，能看来源 |
| 主题归纳 | 基础提取与归纳两阶段配置 | 两阶段状态和结果分清 |
| 时间轴分析 | 分析要求、时间范围与来源 | 时间、事项、依据对应，日期不明确时不能伪造精度 |
| 风险点分析 | 模板关注点、遍历方式 | 输出待核验线索，关联依据和核验入口 |
| 会议纪要分析 | 常规、风险、问答子页及阶段依赖 | 议题、金额、人员与会议来源一致 |
| 合同分析 | 合同类型、检查模板、信息模板、附件 | 合同信息与条款检查分区，能核对正文和附件 |
| 招投标分析 | 项目、单位归组，多模式和模板 | 资料角色明确，待归组和不适用规则可解释 |
| 待摊费用 | 先提取约定，再输入计算基数 | 金额单位、基数、费率、公式和结果可复核 |
| 工程项目一致性 | 表头、映射、模板、阈值 | 评分、差异、源文件与源行对应 |
| 两表项目关联度 | 两个资料槽、字段、权重、锁定等 | 表一/表二不混淆，候选关系不当作已证实结论 |

工具可以保留适合业务的表格、时间线、词云或分栏阅读方式；统一的是范围、动作和状态，不把全部工具强行做成一张相同的表。

### 10.1 最新工具交互要求

- 信息提取：原件与可编辑字段同屏；字段增删/调序、字段说明可选；本次全部资料共用配置；附件合并默认关闭。缺失、证据和置信度分别处理，未返回不得补造准确率。
- 词云：停用词/用户新词可查询、分页、增改删及导入；预检冲突后可逐行/批量忽略或覆盖，保存词库才生效。10–500为展示词数；选择文件后频次随范围重算；词语可查看来源与定位，下次停用不改本次结果。
- 会议纪要：常规分析/风险分析/深度问答；会议/议题/清单视图及全部议题清单；参会与列席人员、万元、扩展字段保留。风险报告七部分不遗漏；常规和风险提示词独立。JSON/Excel导入导出保留金额0、字段、来源及快照。问答Enter发送、Shift+Enter换行，输入法组词不误发。
- 风险点：按层级编辑风险点、检查说明与选用状态；byRisk/byFile均覆盖全部本次范围。按风险点/文件归组；匹配线索、未匹配、资料不足分开；等级仅显示原结果提供的值。
- 时间轴：事项日期来自正文，未知日期独立分组，不能用上传日期补填；日期范围、早晚顺序、分组/逐项展开及来源可操作。
- 主题归纳：基础提取和归纳两阶段独立配置；归纳失败保留基础信息，仅重试失败阶段。
- 共用：结果默认收起配置，按需查看只读快照；搜索/切视图不重新执行。双栏核验左原件、右结果或解析正文，关闭返回原上下文；导出明确全部/筛选/所选/指定文件等适用范围。

## 11. 任务、反馈与错误恢复

**UI-16：界面状态必须对应真实处理状态。** 上传、解析、分析是不同阶段；提交中不能当作执行完成，等待超时不能直接显示成功。生产联调沿用后台任务标识和状态，不要求为 UI 改动重建任务体系。

| 状态 | 用户应看见 | 可执行动作 |
| --- | --- | --- |
| 未开始 / 无资料 | 下一步是什么、需要什么输入 | 添加资料、选择方案 |
| 校验不通过 | 具体字段或资料问题 | 修正、调整范围 |
| 提交中 | 已接收操作，避免重复提交 | 等待；必要时查看状态 |
| 执行中 | 阶段、进度或已处理数量，进度未知时如实表达 | 查看任务；按原能力停止 |
| 部分完成 | 成功、失败、待处理数量及范围 | 查看成功结果、定位失败、重试适用项 |
| 待补充 | 等待用户输入什么，前一阶段成果保留 | 补充基数、映射或资料后继续 |
| 完成 | 本次结果、来源、配置和导出范围 | 核验、导出、开始新分析 |
| 失败 / 中断 | 原因、受影响范围、数据是否保留 | 重试、修正、返回历史 |

局部错误就近展示；轻量成功使用简短反馈，不阻断主流程；需要用户持续处理的问题不能只用短暂 Toast。错误文本按“发生什么 → 影响什么 → 如何恢复”组织，技术堆栈进入诊断，不直接呈现给审计用户。

删除资料、撤销授权、覆盖已有文件等有实质影响的动作保留确认，明确对象与范围。普通查看、展开、搜索和复制不增加确认。可撤销的动作优先给撤销入口，但必须符合后台能力。

### 11.1 任务中心的业务表达

任务中心跟踪各工具AI分析及结果，不与上传/OCR记录混淆。紧凑标题与过滤栏，固定分类、表头和分页，表格内部滚动。过滤支持名称/备注、工具、状态，低频日期/任务类型进入筛选。列表固定任务名称、工具/范围、分析状态/进度、结果及后续操作、创建时间和操作。正文16px，辅助14px，1024×480保留核心列表。

“查看结果”进入对应工具专属工作区；任务信息单独展示进度原因、资料范围与只读配置。行内三点收纳任务信息、备注、终止/删除记录，主结果入口不折叠。返回任务中心保留当前过滤、页码、勾选与滚动。未知业务类型只显示任务信息，不能猜测打开另一工具；招投标与待摊费用虽共享type10，必须依业务类型区分。

结果摘要使用各工具实际返回的业务单位：提取资料/字段、词语/词次、会议/议题、主题/基础信息、事项/日期未知、检查项/线索、项目关系/关联候选、计费约定/费用。文件分析数量与结果行数、风险数量不同，不相互推算。“分析完成”指AI返回结果，不代表审计问题已确认，不新增未经后台支持的人工审核状态。

排队、运行、部分完成、失败、待填写基数、已终止分别表达。进度已知才显示百分比，未知显示待更新；阶段进度与整体进度不能混用。主题归纳失败保留基础信息，只重试归纳阶段；待摊费用第一阶段完成引导填写基数。终止保留已返回结果，删除记录不删除原资料；原失败重试能力继续从对应工具使用。

合并导出支持同一工具至少两项任务跨页勾选，字段不同时取并集，不限制为信息提取或字段完全相同。保留Excel/SQL、三用途及中英字段映射、分文件、有效期、独立导出任务和ZIP下载。运行中任务提交前提示等待完成；部分完成仅导出已有结果，明确遗漏范围。合并/提交/下载均核对权限，原分析快照保留。正式后台链接刷新、重试和30天文件保留仍沿用原服务能力。

## 12. 结果核验、原文与导出

**UI-17：审计结果必须可解释、可追溯。** 结果项尽量提供源文件、对应章节/页码/源行、原文内容和关联资料；位置未获得真实依据时，不伪造页码或精确定位。

核验入口应返回原结果上下文，保留筛选、选中项和滚动位置。快速切换原文时，迟到请求不能覆盖当前文件；无原文、解析未完成、下载失效分别说明并给恢复路径。

正文检索与名称搜索分开。多处命中可逐个定位，关键词高亮同时保留上下文；修改检索词后，明确旧结果需要重新执行。清空检索条件与清空资料范围分开。

导出前明确格式、对象和范围，使用完整结果或完整正文的入口不能只导出屏幕可见部分。导出时重查权限，部分失败说明遗漏项。开始新分析不能覆盖旧任务结果；引用、附件与源文件之间的关系保持可追溯。

## 13. 权限与敏感操作的界面表达

**UI-18：查看、使用、修改和分配权限分别判断。** 不把“能查看”当成“能修改”，不把“能管理资料”当成“能分配权限”，也不把项目根节点“不能直接上传”误标为整个目录只读。

项目、个人、公共空间遵守原有不同规则；引用目录、归档同步目录及系统结构节点不能通过统一 UI 被意外放开。文件上传者等原有例外按源码和后台规则保留，不以“统一风格”删除能力。

常态页头不堆放“项目目录”“查看权限”等标签。资料管理“当前位置”后不显示锁图标；只读等实际限制在相关操作和“目录权限与说明”中以文字说明，不能仅依赖悬停。移除装饰图标不改变权限判断。

未获授权的入口按原规则隐藏或禁用；禁用要能解释原因。打开页面时和提交时都检查权限，权限变化后刷新可用能力；前端隐藏不构成授权，生产授权由后台落实。

## 14. 弹窗、抽屉与层级返回

| 类型 | 使用条件 | 要求 |
| --- | --- | --- |
| 小型确认 | 单个确认、删除等 | 对象、影响、取消和确认明确，不塞入长表单 |
| 编辑弹窗 | 提示词、字段、模板、映射 | 标题清楚、正文滚动、底部保存/取消保持可达 |
| 资料选择器 | 跨空间、目录和分页选材 | 范围暂存；取消回滚；确认后生效；可核对已选清单 |
| 宽型阅读区 | 文本检索、原文对照、完整结果 | 给阅读区足够空间，控制区紧凑、分栏可滚动 |
| 抽屉 | 查看详情、辅助配置 | 不遮断主任务；关闭返回原上下文 |

**UI-19：避免连续叠加弹窗。** 从附件或结果打开原文时可以分层返回，但必须保留原任务上下文；Esc 只关闭当前层。编辑存在未保存改动时，关闭按实际影响处理，不能误保存或静默丢失。

打开后焦点进入弹窗，键盘顺序合理，关闭返回触发点；焦点不落到被遮挡页面。底部动作按“取消 → 确认/保存”的常规方向排列，危险确认有明确危险文案。

## 15. 图标、状态标签与文案

**UI-20：同一功能使用同一图标，不同语义不滥用同一个图标。** 下载用向下箭头，上传用向上箭头，附件用回形针，权限用钥匙/锁，筛选用漏斗，正文检索用文档检索，时间轴与两表关联使用各自独立图形。省略号只表达“还有针对该对象的操作”。

### 15.2 图标颜色与业务文案

工具图标可使用适度不同的低饱和语义色，提高识别；工具名称始终可见，不以彩色图标代替文字。标签只表达会影响当前判断的状态，不把技术类型、权限解释和普通元数据都堆到标题栏。

统一术语：资料管理、提取模板、本次资料、添加资料、上传、文本检索、开始提取/开始分析、核对原文、更多、取消选择、移出本次分析、删除资料。保留专项业务名称如“提取计费约定”，不为文字统一抹平阶段差异。金额明确“元/万元”，时间格式一致，空值使用“— / 未提取到”等明确含义，不能自动解释成0。“解析完成”“分析完成”“需核验”分别指文件处理、任务执行和审计判断，不用孤立的“完成/待处理”计数。取消独立“未关联原文”状态，实际缺原件时仍应如实反馈。

面向用户的业务界面不出现“演示、虚构、原型、示例”等评审标识；技术实现边界记录在交付说明中。错误不能只写“失败”“无权限”，成功不能夸大为“审计确认无问题”。

## 16. 实施与扩展约束

**UI-21：先复用既有能力，再统一表达。** 页面、按钮或菜单调整不改变接口传参、目录父子关系、任务范围或权限模型。正式接入使用已有 ID 与接口；没有后台回执不能显示保存完成。

设计变量统一管理：字号、颜色、间距、圆角、点击区、工具栏高度、收纳阈值、动效等见 [03-设计变量.json](03-设计变量.json)。该文件是规范交付，不是已自动接入的运行时配置；后续开发按现有框架映射，避免增加重复覆盖层。

新增工具复用资料选择、配置编辑、状态反馈、来源核验、导出和历史记录组件。每个新工具应声明适用资料、配置字段、阶段、校验、输出和权限要求，允许业务内容变化，保持操作方式一致。

未经明确的业务变化，不新增权限开关、显示列设置、重复新建入口或额外流程确认。界面修改需核对原代码、功能清单和典型用户路径，不能以删入口换取简洁。

## 其他十项工具与信息提取对齐（2026-10-19）

准备页面统一为三栏，左右等宽：Step 1 添加资料、Step 2 核对原文、Step 3 使用业务含义明确的配置名称。正文及输入16px、辅助说明不低于14px，操作栏不超过56px；1024×480保留三栏，窄屏按步骤切换。添加入口与左栏标题合并，不重复放置中间资料表格；左侧文件单行显示，关联附件与移出采用含义明确的图标。查找和预览均不改变执行范围，移出只取消本次选择，并提供撤销。

资料选择区分“本页”与“全部页”，后者遵循当前目录、是否含子目录及检索条件。仅解析完成、类型受支持且具有分析权限的资料可选，提交时再次校验；表槽维持各自单选。原件和解析文本可切换、可展开双栏核对，编辑右侧配置时保持当前原件页码和滚动位置。

各工具保留独立业务逻辑：词云的本次词表及个人词库；会议的常规分析、风险报告和问答；风险点的层级、勾选与遍历顺序；主题的两阶段要求及失败阶段重试；时间轴的事项日期与未知日期分组；合同的类别、规则、自动分析及附件合并；待摊费用的约定提取、基数输入与费用计算；工程项目的重复/主子项目独立字段和评分配置；招投标的项目、单位、文件角色及三种分析内容；两表关联的双表业务名称、字段映射、硬规则、评分、四项锁定和比较上限。不得为了统一布局而合并这些业务步骤或改写请求参数。

其他工具的“分析方案”保存自身业务参数，与信息提取的字段模板分开。删除通往提取模板管理的错误链接；阶段提示词仍独立编辑，另存个人方案、配置导出和完整配置查看继续可达。

默认工具地址进入可编辑准备页；回看结果使用明确任务地址。历史资料、配置与结果只读保留，停止任务也不得直接修改快照。返回普通工具入口恢复未提交配置；复制新建后再修改。项目归组和双表选择同样作为独立草稿保留。
