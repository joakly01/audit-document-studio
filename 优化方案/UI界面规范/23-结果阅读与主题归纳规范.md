# 结果阅读与主题归纳

更新日期：2026-10-23。本补充优先于历史规范中对应的结果页按钮及主题归纳术语。

## 结果页的操作

信息提取、词云分析、主题归纳的历史结果页，顶部主操作仅保留“导出”，不展示复制新建、本次配置、任务信息、任务中心等重复入口，也不展示准备阶段的步骤导航和资料清单。失败恢复、原文核对、搜索及结果筛选保留在对应内容区域。

任务中心仍固定为“查看结果 / 任务信息 / 导出数据”三项纯文字操作。执行配置从“任务信息 → 执行配置 → 查看完整执行配置”进入，只读保留；新建分析从工具菜单进入。准备页与结果页职责分开，查看旧结果不覆盖新任务草稿。

## 主题归纳的业务顺序

1. 添加分析资料：清单中列出的资料均参与本次归纳，原文预览用于按需核对。
2. 设置归纳要求：用“资料要点”说明每份资料需要摘录什么，用“归纳要求”说明如何汇总同类事项、对照差异。
3. 开始归纳：确认任务名称和资料范围后，自动完成资料摘录与主题汇总。保留两阶段的独立要求、个人方案及执行快照。

默认要求使用事项、单位、金额与单位、日期、原文依据等审计业务词汇，不用泛化的“基础信息”代替业务内容。系统预设、个人预设和本次调整分开；修改须保存后用于本次执行，关闭可放弃草稿。

“方案管理”收纳另存个人方案、导入方案、导出方案，不占据结果阅读区域。

## 主题归纳的成果

| 页签 | 阅读目的 | 展示内容 |
| --- | --- | --- |
| 主题汇总 | 按同类事项阅读多份资料 | 主题、相关要点、来源资料及原文核对；原服务返回的完整主题报告按原文展示 |
| 资料要点 | 逐份核对归纳使用的依据 | 文件名、要点、涉及单位、金额与单位、日期和原文入口 |

主题卡片每页最多8个，资料要点每页20条；单个主题先展示3条，可继续展开。搜索、主题和资料范围使用同一筛选口径。完整主题报告覆盖整批资料，不以文件筛选伪装成局部报告；按文件核对时切换“资料要点”。

主题汇总失败仍保留资料要点，只重试主题汇总。不得要求用户重新添加资料，也不得把重新汇总解释为重跑全部文件。完整报告涉及的来源权限变化时隐藏完整报告，有权限的要点仍可查看。

## 导出及来源

Excel、Markdown、JSON导出本次全部结果时保留主题汇总、资料要点和来源；Excel、JSON还保留执行要求。当前筛选或单文件导出只包含对应要点，CSV只保存要点表。导出窗口说明两者区别；完整汇总未完成或来源下载权限不足时，不导出整批汇总。

原文核对继续使用原件和解析内容双栏。历史结果、个人要求和执行配置互不改写。前端业务术语变化不改变原有两阶段请求字段和任务类型。

验证：`browser_theme_workflow.py`、`browser_extraction_workflow.py`、`browser_word_results.py`、`browser_analysis_workflow.py`、`browser_task_results.py`；涵盖两阶段要求、结果与导出、来源权限、失败恢复、分页和1366/1024×480/390尺寸。正式模型和后台任务服务仍以原系统联调为准。
