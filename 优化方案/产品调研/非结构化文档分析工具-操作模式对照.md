# 非结构化文档分析工具：操作模式对照

调研日期：2026年10月24日。依据官方产品说明、帮助文档及操作示例；本轮未逐项登录商业产品实测。本文是设计研究，不是采购选型、性能评测或已实现功能清单。

## 结论

与审计文档挖掘最贴近的参考有两组：DataSnipper 的审计证据核验与 Hebbia Matrix 的批量文件分析；Rossum 和合合信息 DocFlow 可补充大量文件自动处理、异常复核的设计。NotebookLM/Gemini Notebook、WPS 和腾讯 ima 则提供文档阅读与知识问答的参考。

这些产品存在“在业务工作区配置、运行、查看成果，再按需打开来源”的明确模式。它们有的依托表格，有的依托文档集合或业务收件箱；不能由此推断所有产品都没有独立任务监控。

## 具体产品

| 产品 | 官方资料支持的操作链路 | 可借鉴点及适用边界 |
| --- | --- | --- |
| DataSnipper DocuMine | 在 Excel 写审查问题或使用问题库，分析多份资料，答案与来源引用进入工作区；单条答案卡可进入集中核验视图，人工接受或拒绝答案 | 结果服务于审计核验；分析返回与人工认可分开。可按问题或文件组织结果。参考其证据操作，界面不必照搬 Excel 插件 |
| DataSnipper AI Extractions / Document Matching | 定义字段与模板、批量提取、点击表格值看出处；也可从台账样本出发，映射核验字段与输出列，批量匹配支持凭证 | 区分“从文档取数”和“用文档核对已有台账”，两种业务起点不同；模板可复用 |
| Hebbia Matrix | 向导先选择资料，再把研究问题拆成矩阵列，形成批量分析表；支持筛选后的资料带入下一项分析、Excel 导出及完成通知 | 以“资料 × 分析问题”检查大量文档；长任务可离开并由通知找回。后续列可按前列结果执行，适合事实提取与进一步核查分阶段 |
| Rossum | 文档按类型进入业务 Queue，按预置字段自动提取；需要人工处理的进入 To review，点文档校验原文与字段，确认后批量导出 | Queue 是业务收件箱，不等于算力排队。异常字段优先；其强制纠错后导出适合录入系统，审计场景需保留原始分析与人工核验记录 |
| 合合信息 TextIn DocFlow | 建工作空间，配置文档类别、样本与抽取字段，上传后解析分类抽取；维护审核规则后发起批量审核，查看依据并对照原文件复核 | 国内批量结构化与规则审核的参考；“字段配置”与“审核规则”分工清楚。适合持续重复业务，临时审计分析可简化创建空间和类别的门槛 |
| Google Pinpoint | 在文档集合中搜索、按实体等过滤；提供摘要、对比、提取、时间轴等分析动作。其同版式结构化提取先标注样本、预览抽取值，再批量抽取导出，值与原文框选联动 | 资料集合、探索分析、结果溯源相衔接。应区分同版式标注提取与生成式分析；部分 AI 能力受地区及测试资格限制 |
| Google NotebookLM / Gemini Notebook | 添加和勾选来源，在同一笔记本中提问、生成报告或数据表；答案引用可定位原文，成果可导出 Docs / Sheets | 适合探索性阅读与归纳，来源与成果放在同一工作空间；明确字段、严格逐项核查仍需要专门的结构化界面 |
| Microsoft SharePoint 文档处理 | 将模型应用到文档库，上传后自动处理，提取值成为文档库列表列；既有文件可勾选后分类与抽取 | 固定重复提取可把结果直接融入资料列表。训练和发布模型的流程不宜成为每次临时审计探索的必经步骤 |

国内轻量阅读参考：[WPS 阅读助手](https://plus.wps.cn/blog/p125364.html) 在打开的文档中展开 AI 面板，提供总结、问答和引用页码跳转，以单文档阅读为主；[腾讯 ima](https://ima.tencent.com/download) 强调知识库导入、提问与原文溯源。两者适合参考阅读与问答体验，不能据此推断具备完整的批量审计核查工作流。

## 对现有审计助手的设计判断

以下是结合调研形成的建议，不代表上述厂商全部采取相同设计，也不表示本轮已修改系统。

1. **统一使用流程**：添加资料 → 设置提取字段或检查内容 → 开始分析 → 当前工具查看成果 → 按需核验来源 → 导出或调整后再分析。任务中心补充跨工具跟踪，工具内记录负责找回成果。
2. **结果按审计成果组织**：信息提取以字段汇总表为主；合同、招投标和风险核查以检查事项、判断、依据为主；会议保留时间轴与议题聚类；两表及工程工具以差异、候选关系和源行为主。统一按钮与往返逻辑，保留业务结果形态。
3. **原文按使用阶段出现**：信息提取配置字段时保留原文；大量结果核验时，点击一条结果再打开对应证据，关闭后回原筛选、页码与滚动位置。
4. **分析完成与人工核验分开**：执行状态回答是否排队、完成或失败；结果标识回答是否缺失、冲突或发现待核查线索；人工核验记录审计人员的确认与说明。“未提取到”不能自动等于原文没有，“未命中”不能自动等于无风险。
5. **大量资料先验证设置**：可提供可选的小样本试跑，核对字段和提示词后再处理全部。Pinpoint 的同版式标注提取已有样本预览机制；咱们的具体试跑数量、成本及复用方式需要结合接口另行设计。
6. **优先处理值得核验的项目**：支持从缺失、冲突、执行失败或待核查线索进入，减少逐份翻读。避免把模型自报置信度直接当成可靠的审计评分。
7. **修改与历史保留**：重新分析应明确资料与设置版本，保留原结果；人工说明与原始 AI 输出分开保存。不能把别的产品覆盖输出的重跑规则直接带入现有审计记录。

## 深入核对：从批量分析到连续核验

### DataSnipper DocuMine 的具体做法

会议纪要用例的实际流程是：准备纪要 → 在工作表列出问题 → 选择问题和文件 → 执行 → 查看带来源引用的答案 → 逐项核验。其示例关注预算决定、批准人和会上讨论的风险，输出是可核对的事实与引用。[会议纪要操作说明](https://knowledge.datasnipper.com/en/articles/714304-how-to-efficiently-review-board-minutes-with-documine)

问题库允许从预置业务用例中选择、取消具体问题，再选择资料执行；普通使用者可复用条目，无须每次编写全部问题。[问题库使用](https://knowledge.datasnipper.com/en/articles/714299-how-to-leverage-question-bank-use-cases-in-documine)

Focus Mode 从单条答案卡进入，左侧是问题、答案及来源引用，右侧是原文；可前后切换、接受或拒绝，再回到工作表。这是从汇总结果进入按需证据核验的方式。[官方核验流程](https://knowledge.datasnipper.com/en/articles/714302-how-to-efficiently-review-answers-using-focus-mode)

Answer Refiner 允许调整、补充或移除来源片段，然后重新生成这一条答案。该能力有产品版本要求，不等于所有文档处理接口都支持局部重跑。[官方答案修正流程](https://knowledge.datasnipper.com/en/articles/714301-how-to-edit-ai-generated-answers-using-answer-refiner-in-documine)

需要明确两项边界：官方提问指南建议一问一事、给出具体条件、避免依赖未提供的外部背景，侧重事实型问题；不能将其用例理解为直接自动认定审计问题。[问题编写指南](https://knowledge.datasnipper.com/en/articles/714297-guide-to-writing-questions-for-documine) 另据会议用例，拒绝答案会删除答案及其关联引用；本助手应继续保留原始输出和核验意见，不能直接照搬删除规则。

### Hebbia Matrix 的具体做法

列管理集中处理列名称、顺序、提示词及批量操作；引用预览可就地看到来源内容。可借鉴其集中管理分析内容与轻量查看证据的方式，保留本助手现有的系统/机构/个人提示词分类。[列管理](https://www.hebbia.com/blog/whats-new-may-disclosure-2026)、[引用预览](https://www.hebbia.com/blog/the-disclosure-december-2025)

官方界面示例：[列管理参考图](https://images.ctfassets.net/bn476u6z5acg/695ysMTP9TE37lwA27vvMc/f1c73a7593052e73dd0f1fc318ab13ad/MayDisclosure_ColumnManager.jpg)、[引用预览参考图](https://images.ctfassets.net/bn476u6z5acg/Bq1f2WdoqEaLZUwYDCITv/5d257fcc7d1608cb0b491766ab5e1ff3/DecemberDisclosure_Citations.jpg)。图片用于理解布局，不把营销示例数据当成核验过的事实。

## 与当前前端的差异及调整顺序

本节为只读源码核对及后续设计建议，本轮未修改业务代码。

**已有能力直接保留：**

- 信息提取已有资料×字段结果表、点击取值进入原文/字段双栏，以及上一份/下一份文件。对应 `extraction-workflow.js` 的 `ewResults()`、`ewReviewMarkup()` 和 `ew-review-prev/next`，不再把它们当成待新增功能。
- 各工具已有当前页结果、工具内分析记录、调整后再分析。对应 `tool-session.js` 与 `result-actions.js`，独立草稿和历史任务保持。
- 现有提示词库与提取模板已能复用分析内容。保留 `prompt-guidance.js` 的公共、机构、个人分类；不另建重复的“问题库”导航。信息提取模板仍按用户要求默认不选。
- 会议已有时间轴、议题聚类及定位。对应 `meeting-timeline.js` 的 `mtTimeline()`、`mtDetail()`、`mtLocate()`，保留其业务阅读方式。

| 顺序 | 具体建议 | 源码差异与接口边界 |
| --- | --- | --- |
| 近期优先 | 合同等结果把检查事项、判断依据与原文合在同一按需核验视图；支持当前筛选结果内的上一条/下一条，关闭回原列表 | `contract-workflow.js` 当前由 `cw-result-detail` 再打开 `source`，核对需要多次进出。可复用现有原文查看器；精确页码和高亮必须依赖实际返回，不能仅凭文件 ID 伪造定位 |
| 可选增强 | 记录“已核对 / 存疑”及核验意见，独立于模型输出；不增加强制审批，不影响原导出入口 | 当前合同的“待核验”来自模型 `judgment`，不是人工确认状态。正式保存需要任务、稳定结果标识、操作人、时间、意见和轻量接口；不能用数组下标作为长期标识 |
| 按场景增加 | 逐文件提取、合同和逐文件风险核查可先做小样本验证，再跑全部 | 可沿用原执行接口创建明确的小范围任务。招投标需保留完整项目与文件角色；会议跨期分析需完整时间范围，不能统一随机抽取几份替代整体关系检查 |
| 接口支持后再做 | 针对某字段、某检查项补充资料后局部重新分析 | 当前 `retry-task` 主要处理失败任务，`newAnalysis()` 是复制输入后新建任务。局部执行与结果合并需要稳定标识、版本和明确接口语义；在此之前继续使用调整后再分析并保留旧结果 |

建议的日常操作仍保持：选资料 → 确认字段/检查内容 → 执行 → 在当前工具看成果 → 点击结果核对依据 → 可选记录意见 → 导出。统一入口、状态语义和返回规则；各工具继续展示适合自身业务的成果。

## 合合信息：宏观流程可借鉴之处

本节聚焦 DocFlow。官方合同示例明确将一次性配置与日常处理分开：工作空间、文件类别、字段及规则库配置完成后，后续合同可以直接沿用。日常链路是上传合同、取得分类及抽取结果、绑定已有规则库发起审核并获取结论。[已有配置的日常合同处理](https://docs-docflow.textin.com/docflow/cn/00-overview/contract_review_already_configured)

可借鉴的宏观结构如下：

- 配置流程：确定业务场景 → 配置资料类别、提取字段与审核规则 → 保存复用。
- 日常流程：归集本批资料 → 解析、分类与抽取 → 规则核查 → 查看结果和依据 → 复核、输出。

这两行是对公开文档的流程归纳，不代表全部环节都要求用户逐步点击，也不保证每一项均为当前 Web UI 的独立页面。

**对本助手的建议：**

1. 日常操作优先暴露“选资料、确认检查内容并执行、看结果”三个阶段。常用字段与规则在原有模板/提示词功能中维护，临时调整留在工具内；信息提取模板默认不选的约定保持。
2. 同一项业务内连续完成事实提取与规则检查。合同分析可以显示合同要素及检查结果，用户无需先手动到信息提取工具取数、再重新选择资料进入合同工具。后台分阶段可继续保留；这不是要求合并全部工具。
3. 以本批业务资料作为处理范围。合同、发票、收货资料之间的核对有跨文档关系；招投标已存在的项目、文件角色、投标单位分组应保留。原有公共/项目/个人空间继续管理归属，不再新增重复的资料空间。
4. 将材料处理状态、分析执行状态和业务核查结论分开。资料解析成功不代表已完成规则审核；审核不通过也不同于执行失败。结果应能回到对应资料和判断依据。
5. 业务成果在当前工具承接；任务中心集中展示运行与跨工具历史。官方文档能确认结果可在对应工作空间查看，不能由此推断 DocFlow 不存在独立任务页面。

DocFlow 面向相对稳定、重复发生的企业处理业务，本助手同时面对临时审计探索。因此建议借鉴它的流程组织与配置复用，继续允许临时选择不同资料、调整本次要求，避免把建立空间、训练类别、配置规则库变成每次分析的必经动作。

依据：[产品使用流程](https://docs-docflow.textin.com/docflow/cn/00-overview/intro)、[合同完整配置与处理](https://docs-docflow.textin.com/docflow/cn/00-overview/contract_review)、[跨单据关系核验与结果回写](https://www.textin.com/product/textin_docflow)。公开的 API 流程与产品说明用于确认业务链路；未登录 Web 产品逐项实测。
