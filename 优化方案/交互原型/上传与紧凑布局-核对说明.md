# 上传与紧凑布局核对说明

日期：2026-10-18。原「前端代码」、截图与会议材料未修改。

## 入口与业务流程

资料管理不再单列「资料管理 / 资料数量 / 上传」标题栏。当前位置、名称搜索、上传及更多合并到一条约58px操作栏；文本检索进入更多第一项，范围及筛选按实际区域宽度收纳。取消独立标题栏后，再取消42px位置行，累计回收约90px核心高度，不缩小业务文字。已选数量和取消选择并入原分页栏。

上传主按钮打开文件选择弹窗，下拉明确区分「上传文件」和「上传文件夹」。工具内「添加资料」的选择器也提供上传资料；上传后返回原选择器，保留暂选清单，由用户确认加入工具。

文件夹沿用原流程：选择目录 → 已有同名目录时提示合并 → 按类型筛选 → 按完整相对路径处理重名 → 上传并解析。保留文件夹、子目录和同层文件；不同子目录下的同名文件不误判重复。类型筛选提供仅文档、排除压缩包、排除可执行文件、全选、全不选，默认排除压缩、执行、临时及系统文件；全不选时可仅创建目录结构。

重名默认跳过，可逐项覆盖；覆盖保留旧版本供历史任务引用。上传时再次检查目标目录、子目录、覆盖权限、个人空间额度、文件/文件夹名称碰撞。单文件上限与原 beforeUpload 一致为100MB，超过上限不入库。

支持文件夹选择 API、兼容目录输入框与目录拖放。前者和支持目录条目的拖放可保留空子目录；兼容 webkitdirectory 只能取得包含文件的路径，浏览器不返回的空目录无法还原。完全空的根文件夹按原系统提示为空，不伪造上传成功。失败解析保留原因与重试入口。

当前交互项目沿用浏览器本地数据适配器；未接入内网服务器，也未声称实现服务端分片续传或Redis恢复。真实原文件保存在浏览器，解析仍受格式、OCR和浏览器资源限制。正式接入只调整视图和适配器，保留原接口、权限与上传服务。

## 小窗口与嵌入

位置与操作合并为单行后，中间资料表直接承接操作栏。外层框架应给子页面明确的可用高度；页面按自己的可用视口计算，不按显示器分辨率猜测。修复浏览器区域的网格/弹性最小高度，目录、表格与工具箱独立滚动，分页固定在资料区底部。窄屏工具箱按需侧向展开，不挤占资料高度。

验证：上传13组、资料管理14组、检索权限10组、单行操作5组/10布局，以及6种视口的已选/未选12布局和真实iframe预留80px框架栏场景。证据见review/folder-upload-results.json、review/library-height-results.json及对应截图。

## 位置列

资料列表固定显示名称、文档状态、所有者、位置、上传时间与操作。位置为当前资料所属空间与文件夹路径；文件夹行显示父目录，长路径省略显示并提供完整提示。窄屏仍保留位置列，使用表格区域内部横向滚动，操作列继续固定右侧，不恢复显示列设置。验证记录见review/location-column-results.json。
