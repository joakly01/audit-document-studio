# 两表项目关联度：工作区与源码核对

更新日期：2026-10-23。原 Vue 源码保持不变，界面优化只进入现有 Sites。

## 审计操作

1. “Step 1 选择两张台账”：先选待查台账，再选用于核对的另一张台账。分别填写业务名称，单槽更换文件，两张表不可相同；文件名可按需打开原件及解析正文。
2. “Step 2 对应字段与比较规则”：主区展示表一字段、表二字段、比较方式及权重。先确认比较哪些内容，再开始分析。提示词单独选择与编辑，仍支持系统及个人来源。
3. 需要调整时进入“调整字段与规则”，分为字段与评分、判定与比较范围、优先判定规则。修改只保存在草稿，明确保存后应用；历史任务只读。
4. 结果中按完全一致、不完全一致、表一独有、表二独有查看实际返回内容，从“查看源行”逐字段核验。关联候选不等于已确认的项目关系，配对未返回也不等于无关联。
5. “进一步筛选”针对已返回的配对组，独有记录保留；可恢复全部结果。导出保留当前筛选及原始源列、数值0、布尔false、对象等内容。调整后再分析仍创建独立草稿，不改原任务。

## 源码核对矩阵

| 原前端功能 | 本次保留方式 |
| --- | --- |
| 两个独立文件槽及业务名称 | 左栏两张台账卡片，选择/更换/移出均按槽执行，取消选择不改变另一个槽。 |
| 动态真实表头 | 只从已选文件实际列中映射，不以默认台账列冒充当前表头；执行前校验映射完整。 |
| 相似度、金额差异、完全相等 | 字段编辑保留三种比较方式和原阈值（原组件范围0–5），默认值分别0.8、0.04、0。 |
| 字段权重与0–5评分规则 | 每字段完整编辑，权重合计校验，保留预筛与最终加权评分的区别；小数权重不四舍五入为0。 |
| 完全一致/不完全一致阈值 | 完全一致为严格大于full，不完全一致为大于等于partial且未达到完全一致。 |
| 标准/批量模式 | 标准模式隐藏但保留批量上限草稿；批量显示每行1–20对、总计1000–50000对，保留截断说明。 |
| 最少匹配字段与4项锁定 | 配置全部保留并进入执行快照，不简化成单一“锁定最佳候选”。 |
| 单字段与AND组合硬规则 | 业务标题为优先判定规则；仍支持增删条件、优先级、结果、说明及恢复提示词规则。 |
| 新增/移除字段与评分草稿 | 一览表分页检索，逐项编辑。移除字段时同步移除引用它的规则，外层取消可整体还原。 |
| 关联提示词与配套规则 | 使用现有逐环节提示词库、覆盖前确认、个人另存与重新选择逻辑。 |
| 比较请求派生字段 | 保留字段映射及logical/complete/numeric/table fields、两张文件引用与业务名称。 |
| 原四区结果和完整列 | 支持compare_response及yz/bwqyz/ggdyxm/tzxmzxsp形态，展示实际源字段；不根据配对缺失推断独有。 |
| 原AI二次筛选API | 以task_uuid和prompt交给适配器，接收按yz/bwqyz分区的组级decisions；两独有区不变，可恢复。 |
| 导出和来源权限 | 当前筛选完整导出，显式任务外UUID、refs或不可读来源不能通过替代文件绕过；需要两个来源的配对整体隐藏。 |

## 验证及联调边界

`tests/browser_association_workflow.py` 检查双表角色、取消与草稿隔离、全部参数与组合规则、1000映射分页、四类结果、0/false/额外列、原组级决策、当前筛选JSON导出和恢复、显式任务外来源/权限、历史只读与再次分析，以及1366×768、1024×480、390×600布局。记录为 `review/association-workflow-checks.json`。

当前仍为浏览器本地交互原型。`window.auditAssociationRefine({task_uuid,prompt})` 为原二次分析接口的接入点；没有正式服务时，仅演示明确的评分/关键词筛选条件。其他自然语言要求会说明尚需接入服务，不假装模型已理解。后端比较、预筛、并发、编码迁移和精确评分仍应由原接口/算法执行，本次没有在浏览器伪造正式审计结果。
