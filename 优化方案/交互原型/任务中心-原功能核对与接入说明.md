# 任务中心：原功能核对与业务设计

2026-10-19。本轮调整集中在 `dist/task-center.js`、`dist/task-center.css`。原工程 `前端代码/` 与原 API 均未修改。覆盖当前11项工具，结果页面继续复用各工具自身实现。

## 1. 业务定位

任务中心集中跟踪一次次 AI 工具分析，并找回各工具的成果。它既不是资料上传/OCR记录，也不是所有结果共用的通用表格，更不是“审计问题已确认”的登记台。

用户进入后要能回答：哪项审计分析、用了什么工具、分析到哪一步、已经产出什么、在哪里继续。任务信息承担范围、配置、原因与备注，分析结果承担对应工具的业务阅读和原文核验。

## 3. 列表与入口

紧凑标题及一行过滤工具栏；全部/处理中/需跟进/已完成/已终止为同一列表的分类。计数基于当前过滤范围，不把当前页数量当总量。搜索支持任务名称及备注；工具、原始状态、任务类型、创建日期可过滤，分页支持10/20/50。

固定列：选择、任务名称、使用工具/资料范围、分析状态与进度、结果与后续操作、创建时间、操作。任务名称最多两行、备注一行省略，完整值可悬停查看。状态不只靠颜色；文件“成功/失败/待处理”指工具分析，资料解析另外记录。

主入口按实际状态显示：查看进度、查看结果、查看基础信息、填写计费基数、处理失败、下载文件。行内实心三点只放任务信息、修改备注、终止/删除记录。菜单在低矮窗口内定位；支持方向键、Esc与焦点返回。

“分析完成”只表示本次AI结果已返回。没有增加未经后台支持的人工“已审核”状态，没有把风险线索变成已确认问题。

## 4. 各工具结果路由与含义

| 工具 | 原task_type / biz_type | 列表摘要与结果入口 |
| --- | --- | --- |
| 信息提取 | 1 | 返回资料数、字段数；提取信息表、缺失值、字段证据与原文 |
| 合同分析 | 2 / contractCompleteness | 条款检查数；条款、基础信息、依据与报告 |
| 时间轴 | 3 / timelineAnalysis、timeline_analysis | 事项数、日期未知数；事项时间轴及来源 |
| 词云分析 | 4 / wordCloud、wordCloudAnalysis | 词语数、出现次数；词云/词频及出处，不代表风险 |
| 主题归纳 | 5及主题相关biz_type | 基础信息与主题分别表达；归纳失败先看基础信息，单独重试归纳 |
| 工程项目一致性 | 6 / engineeringProject等 | 项目关系候选数；重复/主子项目、量纲与源行 |
| 会议纪要 | 7 / meeting_minutes、meetingMinutes | 会议资料及议题数；常规议题、风险报告、深度问答 |
| 风险点 | 8 / riskPointAnalysis | 检查项、未匹配线索数；按文件或风险点核对内容与依据 |
| 两表关联 | 9 / associationDegreeTwoTables等 | 关联候选数；两张表、分数和对应源行 |
| 招投标 | 10 / biddingAnalysis | 招投标检查项；按项目、单位和分析模式查看结果 |
| 待摊费用 | 10 / prepaidExpenses | 第一阶段约定已提取，待填基数；第二阶段才有计算费用与报告 |
| 合并导出任务 | is_merge_export_task / 本地kind | 来源任务数、生成文件数；独立配置/文件下载，不进入分析查看器 |

所有摘要只计已返回的结果，不用文件总量推断风险数。结果缺失时显示“未返回可展示结果”，不判断为无问题。主题阶段重试不清空成功提取的数据。停止归纳后，延迟回调不能把已终止状态改回完成。

## 5. 任务信息与失败恢复

任务信息分“进度与结果、分析资料、执行配置”。显示实际失败原因；没有原因时说明未收到具体原因，不能编造模型错误。资料页显示当前原文权限和对应分析状态；配置只读。修改任务备注不会修改资料、配置或结果。

终止需确认：保留已返回内容、范围及配置；排队任务也可终止。删除只删除任务记录，原资料保留；正在运行必须先终止。失败进入原工具，按已有失败重试能力处理，复制新建保留原任务。

## 6. 合并导出

至少两项相同工具任务，可跨页选择；实际工具标识相同才可合并。合并导出记录不能再次合并。字段不相同取并集、缺失值保留为空，不靠相同字段列表作限制。

导出任务保留来源任务名称/编号、配置及已有结果快照。支持Excel、神通SQL建表及分批INSERT，三用途字段映射分别保存（Excel表头、SQL字段、SQL注释），各自中文或英文。英文初始编号明确可编辑，不冒充自动翻译。字段空值、重复、SQL标识、行数、有效天数均校验。分文件按实际结果行数，ZIP文件名使用UTF-8。过期可在30天文件保留期内刷新下载有效期；生成失败可按原配置重试，不覆盖源任务。

合并前、提交时及下载时检查资料下载权限；权限变化阻止下载，不凭旧快照继续导出。部分完成仅导出已有行，并在导出详情解释。源分析结果和配置不被改动。

## 7. 正式接入边界

当前站点为浏览器交互工程：任务保存在本浏览器，执行进度/结果由既有本地规则驱动；本轮导出真实生成Excel/SQL/ZIP，但没有调用正式AI或数据库执行。浏览器刷新时中断的本地排队/运行任务显示已终止，不假装有后台持续执行。

正式工程须继续：

1. 使用PageList过滤/分页、真实total及原批量轮询；分类统计应使用服务端同范围计数。刷新操作拉取任务及进度，不重启分析。
2. GetTaskSchedules按业务类型装配各查看器；保留task_uuid、analysis_id、file_uuid、selection_summary、配置快照及运行步骤树。会议/时间轴等需要的分析ID缺失时取详情补齐，失败给可恢复提示。
3. progress_context的stage和overall分别接入；无数值时不补0%、不自动100%。成功/失败/待处理文件数与结果行数不同。
4. 失败重试使用RetryFailedResults，仅处理失败文件/阶段；终止仍按原服务停止能力和delete接口语义办理，避免把“终止”误接成永久删除。
5. 合并字段来自BatchMergeExportFieldSources；提交MergeExportCreate原export配置，包括execute_mode/task_switch、三用途语言/字段映射、每文件行数、file_expire_days。导出详情接原下载URL、RefreshUrls、Retry和ZIP接口。服务器文件保留30天与预签名链接最长7天分开管理；链接过期能刷新且须重新鉴权。
6. 后台负责权限、任务隔离、AI持续执行、并发/幂等、数据库方言及文件保留；前端本地下载校验不能代替服务端授权。当前SQL下载测试只验证文件结构和映射，不等于神通数据库兼容性验收。

## 9. 分析记录与运行监控（2026-10-22）

本次按照业务使用与执行监测的区别，在任务中心标题同行设置“分析记录 / 运行监控”两个视图。默认进入分析记录；共用同一批有权限的任务，不复制任务，不新建第二套结果数据。

- 分析记录：按工具与业务名称查找结果，继续填写计费基数、处理失败、核对原文、合并导出。11种工具仍使用各自结果页面。
- 运行监控：默认查看进行中任务，可分别查看排队、执行、需关注及全部任务；查看阶段、整体进度、资料成功/失败/尚未完成数、用时、最近进展与异常原因。运行详情可核对资料与只读配置，终止仍需确认。
- 运行中任务的“查看进度”进入运行详情；完成结果从分析记录进入对应工具。运行监控不放结果合并操作，切换视图保留业务侧已有合并选择。
- “需关注”包括执行失败、部分完成、归纳失败，以及已有进度时间但超过10分钟没有更新的执行中任务。此时间阈值仅用于交互提醒，不将任务改成失败，也不能证明模型卡死；正式接入宜按工具和阶段采用后端提供的阈值。待填计费基数属于业务待办，不当作运行故障。
- 进度时间、开始时间未记录时显示“—”；排队时间可从提交时间计算。不用列表排序推算全局排位，不用平均耗时生成假预期。运行态有实际队列数据时才显示前方任务数和预计等待时间。

原前端 `api/task.js` 已有 `getTaskRuntimeAPI`（`/api/v1/task/runtime/{task_uuid}`）；原任务详情使用 `runtime_nodes` 或 `step_tree` 和独立的失败原因。正式接入继续使用这些接口与原阶段进度结构，不能把任务备注当故障日志。当前监控层可接收以下规范化字段（不是对原API字段已存在的承诺）：

| 字段 | 口径 |
| --- | --- |
| startedAt | 当前执行轮次实际开始时间，不能用创建时间替代 |
| lastProgressAt | 最近一次执行阶段/进度实际更新的服务端时间；点击刷新不能改写 |
| completed / finishedAt | 执行结束时间 |
| queuePosition | 服务端调度返回的前方任务数，0表示前方无任务；不一定立即执行 |
| estimatedWaitSeconds | 服务端提供的预计等待秒数；未知时不显示 |
| error / errorMessage / failureMessage | 实际失败原因，不读取用户备注来猜测错误 |

当前交互原型未接正式调度器，上述信息缺失时保持未知；此轮界面调整不代表解决模型并发、超时或崩溃。平台级模型资源、全局队列、并发配额、重试与日志应作为有运维权限的管理能力，不能向普通业务用户暴露全部人的任务。正式联调需验证：多任务并发不阻塞UI、任务可靠排队、超时与失败可恢复、重试幂等、关闭浏览器后后台继续执行、权限与结果隔离；不能仅凭前端演示认定这些能力通过。

验证：`tests/browser_task_monitor.py` 检查视图隔离、运行详情、未知数值、进度停更提醒、跨页、终止、结果返回和三尺寸布局；原 `browser_task_center.py` 继续检查11项工具路由、权限、合并导出与历史快照。

本地交互执行、归纳阶段重试与合并导出会记录实际开始、进度更新及结束时间；刷新页面数据不会改写进度更新时间。打开的运行详情随执行更新，结束后提供对应工具的结果入口。


## 10. 审计分析结果集合与三个直接入口（2026-10-22）

“分析记录”改为“分析结果”，强调审计人员获取成果、核对依据及带走成果的目的。保留运行监控；主列表仍可查找处理中、失败与待跟进记录，状态不伪装为已生成成果。表格提交时间移至分析名称下方，压缩重复阶段文案，给成果摘要与直接操作留空间。

三个常用操作始终直接展示，采用不同语义图标和文字：

| 操作 | 图标 | 行为 |
| --- | --- | --- |
| 查看结果 | 眼睛 | 进入对应工具的既有业务结果页面，保留11项工具差异 |
| 回溯配置 | 参数滑杆 | 进入该任务的只读配置页面，可查提交时的资料、附件、字段、规则及阶段要求 |
| 下载结果 | 向下下载箭头 | 进入该工具的成果下载页，再选择所需成果及格式/范围 |

回溯配置复用原工具配置控件与查看弹窗，历史任务不可直接修改。信息提取字段、风险检查点、词库选择、阶段提示词、合同规则、项目分组、两表字段对应与比较规则均保留。回到工具默认入口恢复未提交草稿，查看历史不覆盖草稿。

下载页按业务成果命名：信息提取表、词频明细及词云图片、主题归纳与基础信息、事项时间轴、风险线索、会议议题与已生成的风险报告/问答、合同检查表与报告、招投标检查表、计费约定与已生成的费用报告、项目关系候选、两表关联候选。复用现有各工具导出逻辑，不用一份通用报告取代所有结果。表格下载采用业务列名，保留原文依据与本次配置。部分完成只下载已返回内容；未生成的会议风险报告和费用报告不提供虚假下载。

排队/执行中、失败或已终止且不可展示结果时，“查看结果”和“下载结果”保留位置但禁用，回溯配置可用；失败原因和终止操作仍在任务信息/运行监控。资料下载权限在入口及确认时复核；合并导出继续沿用原独立任务逻辑。当前仍为浏览器交互工程，正式服务端需按任务身份读取真实配置快照、权限和各工具产物。
