# 待摊费用：两阶段核算与源码核对

更新日期：2026-10-23。本轮只更新 Sites；原 Vue、正式接口与外部服务器未修改。

## 使用流程

准备页采用“Step 1 计费合同 / Step 2 设置费用核算”两栏。左侧添加合同、关联补充协议与移出本次选择；文件名按需打开原件和解析正文。右侧选择费用类型，分别选择、编辑计费约定提取与费用计算的提示词。三个简短步骤说明先提取、再确认基数、最后核验报告，避免把两阶段理解为一次立即完成。

第一阶段完成后，结果页显示逐合同的“计费约定”和原文入口，并提示填写“计费基数（元）”。同一个任务的多份合同使用同一任务基数；界面明确基数的适用范围。点击“计算并生成报告”继续当前任务，不另建任务，也不修改第一阶段执行配置。

报告按合同分别列出计费约定、计算过程、金额和原文。有未取得有效条件或费用类型不一致的资料时明确显示“未计算”，金额只对实际已计算记录小计。报告、Excel/CSV/Markdown/JSON和任务中心入口保留。完成后基数只读；“调整后再分析”复制为新草稿，保留原任务及历史结果。

## 原功能核对

核对 `前端代码/views/document-mining/PrepaidExpensesPrototype.vue`、`PrepaidExpensesPrototypePage.vue`、`components/PrepaidExpensesLeftSidebar.vue` 和 `prepaidTaskProgressUtils.js`。

| 原前端功能 | 本轮处理 |
| --- | --- |
| 六类费用 | 工程监理、工程设计、代建管理、造价咨询、勘察测绘、招标代理全部保留，不能把固定类型压缩成只支持监理费。 |
| 两个独立提示词 | 提取计费约定与费用计算分别使用系统/个人提示词、分别编辑和另存，保留提示词实际ID。 |
| 创建提取任务 | 对齐 `exec_mode=custom`、`parameter_settings.exec_phase=extract`、费用类型编码/名称、两提示词ID及内容、空基数。 |
| 同一任务继续计算 | 保留 `task_uuid` 和 `billing_base_wan` 请求结构；原 Vue 的界面与数值单位实际为元，不能因历史字段名自行除以或乘以10000。 |
| 多资料同一任务 | 保留一个任务基数作用于多个文件的原分支；原型按逐文件约定分别测算，不把第一份合同的费率套用到全部资料。 |
| 提取和计算结果分开 | 保留 `text_1 / billing_agreement_text` 计费约定及 `phase=calculate` 的 `calculation_result_text / raw_dify.output,text_1,text_2` 报告；同一文件多个阶段记录合并展示，不重复计费。 |
| 结果报告 Markdown | 使用现有转义渲染器显示实际返回的报告，保留段落、标题、表格；下载提供 Word 与文本。 |
| 阶段恢复 | “待填写计费基数”可从任务中心回到同一任务续填，已生成报告的任务不误回到待填状态。 |
| 权限与历史 | 展示、报告和导出检查所有必要来源；任务外来源、不可读/不可下载的必要证据不得泄漏。历史配置只读，重新分析沿用独立附件快照。 |

## 原型边界

六类示例文件的比例或固定价是各自虚构合同中的约定，不是政府收费标准。原型只对已保存的示例计费条件进行算术演示，不从未识别的正文猜测费率，不调用真实费用计算模型。实际服务返回的复杂规则、取费条件、调整系数及完整计算报告，仍需按原接口联调；本轮保留原报告输出内容，不用简化本地公式替换正式模型报告。
