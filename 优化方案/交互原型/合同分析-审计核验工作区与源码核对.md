# 合同分析：审计核验工作区与源码核对

更新日期：2026-10-23。只更新现有 Sites，不更新外部服务器或生成交付部署包。原 Vue 源码未改动。

## 审计人员如何使用

1. 在“Step 1 合同资料”添加本次检查的合同；补充协议、技术要求等从对应合同的附件图标关联。资料名称可打开原件与解析正文，不常驻大面积预览。
2. 在“Step 2 设置合同检查”选择自动识别、施工类或非施工类。手动类别的检查事项以表格显示，勾选本次要执行的规则；搜索、翻页不改变其他页的勾选。提示词和附件合并选项放在独立页签。
3. 点击“开始分析”确认后生成新任务。完成后先看“检查结果”，按合同和判断结果筛选；从“查看依据”阅读提取内容、判断依据、判定标准与分析说明，再按需核验原文。
4. 合同基础信息、报告和数据导出均保留。需要修改检查要求时使用“调整后再分析”，沿用资料、附件和执行配置生成独立草稿，原任务不变。

AI返回的条款和风险线索用于进一步核验。“已提取”不等于“符合”，未返回判断依据或风险结论时如实标注，不把模型文本当作已确认审计发现。

## 原前端功能与本次保留方式

核对 `前端代码/views/file-manager-code/ContractViewer.vue`、`components/contract/ConfigPanel.vue`、`components/contract/ResultTable.vue`、`utils/contractDisposalParser.js` 与 `composables/useContractReport.js`。

| 源码关系 | 本次界面及数据处理 |
| --- | --- |
| 自动识别合同类别与额外自动分析是独立参数 | 类别选择与“补充查找线索”开关独立；开关不自动提交任务。自动类别忽略留存的手动规则和提示词。 |
| 自动类别可直接执行；手动类别无规则时须开启额外分析 | 校验保持这一分支，不强制自动类别填写规则/提示词，不阻断合法的无规则补充分析。 |
| 施工与非施工模板按类别获取 | 各类别保存独立规则草稿，切换不串用；源码仓库未提供实际规则模板及法规全文，原型不伪造生产模板或法规。已有草稿保留。 |
| 规则含四项必填内容 | 编辑弹窗完整保留名称、说明、判断依据、判定标准；主清单呈现名称与说明，避免整屏展开所有文本框。 |
| `extracted_value` 可为文本或对象 | 保留文本与分字段格式切换，两类草稿来回切换和重新打开均保留；数值0、布尔false和对象不丢失。 |
| 合规检查与基础信息提取有两个提示词 | 分环节独立选择系统/个人提示词，编辑及另存保持现有逻辑；不把整个工作区误称为提示词。 |
| 返回规则检查及额外自动分析内容 | 明确区分结果来源，保留实际判断、提取内容、依据、分析及补充文本；不以“已提取”替代符合性判断。 |
| 报告独立生成并下载 | 保留生成/处理中/失败重试/查看流程；提供Word与文本下载，不重复运行合同分析。 |
| 历史快照与再次执行分离 | 历史规则只读，沿用配置再分析时复制资料与附件，不修改原任务和资料库关联。 |

## 请求与结果的边界

执行快照按原结构保留 `exec_mode=custom`，`custom_config.contract_category` 对应 `auto / construction / non_construction`，保留 `parameter_template`、`prompt_uuid` 及 `button`。自动分支的 `parameter_settings` 只提交 `button`；手动分支提交选中的 `information_extraction`、两个提示词及 `button`。

规则提交使用 `title / description / laws_and_regulations / judgment_rule / extracted_value`，不把界面格式选择、双缓冲和分页等辅助状态混入原参数。附件合并保留为当前应用的关联快照及选择能力，不臆造原合同接口不存在的请求字段。

结果中的文本、键值对象、0和false完整显示与导出。true / false在界面显示“符合 / 不符合”，原始值仍在JSON中保留。单条结果引用多个来源时全部检查读取/下载权限；任务外来源、缺失或已删除文件不能替代为其他可见文件。CSV、Excel、Markdown使用中文业务列名，JSON保留原始结果、执行配置及附件快照。
