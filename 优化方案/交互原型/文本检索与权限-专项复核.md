# 文本检索与权限专项复核

更新：2026-10-18。本文件补充并修正上一版资料管理设计，权限入口与文本检索以本轮实现为准。

## 一、发现的问题与处理

文本检索上一版已经有入口，但位置不突出，且完整性不足。重新对照 `Index.vue` 1870–2087、2530–3050 后，发现需要按原系统保留的不只是“输入词语查一段内容”，还包括独立选资料、首份正文预览、匹配文件勾选、正则、文件内容导出和继续分析。

本轮还发现并修复了实际范围问题：检索结果带入工具时，上一版会与资料管理已选清单合并，可能夹带未在检索结果中勾选的文件。现在只带入检索结果勾选文件，主列表已选清单单独保留。

上一版权限也过于宽泛：项目目录与个人目录出现通用授权入口、把 FULL 管理权限视作可授权，以及机构绑定不区分空间。这些均已调整。

## 二、文本检索保留与增强

| 原能力 | 当前界面与交互 |
| --- | --- |
| “更多—文本检索” | 原入口保留，搜索栏旁增加常用入口；与“文件名称搜索”明确区分 |
| 未勾选也能进入 | 显示选择资料引导，不要求先回主列表勾选 |
| 同步主列表勾选 | 进入检索时复制当前可访问范围；检索范围与主列表清单各自独立 |
| 独立文件选择 | 跨空间、目录选择；确认更新范围；取消返回原范围、结果及勾选 |
| 首份文件预览 | 未检索时先预览范围内首份资料正文 |
| 正则匹配 | 支持关键词、正则与大小写选项；语法错误有明确反馈 |
| 检索结果 | 显示匹配文件数、每份命中数、资料位置和正文上下文 |
| 多处高亮 | 当前命中突出，上一处/下一处循环定位，可切完整正文；上下键切换结果文件 |
| 已选范围与命中勾选 | 两个集合分开，预览不会改变导出或分析范围 |
| 清空检索 | 清掉条件、命中和结果勾选，恢复原检索资料范围 |
| 清空资料 | 清掉本次检索范围，不删除文件，不改主列表已选 |
| Excel 导出 | 导出所勾选文件的完整正文和路径，长正文按行分段，避免单元格上限截断 |
| Word 导出 | 与原系统一致，逐文件生成 DOCX 并打包 ZIP，包含完整正文与来源 |
| 继续分析 | 只使用检索中勾选的文件；格式不适用或未解析的资料列明原因，确认后再进入工具 |
| 关闭后重新进入 | 新的检索会话，重新复制主列表范围；原文弹窗关闭则返回原检索状态 |

额外处理：有未解析或无正文资料时说明未纳入检索的数量；关键词修改后提示当前结果仍属于上一次检索；零匹配保留资料范围；正则在可终止线程中执行，超时自动停止，也可主动取消。每份正文最多展示前 2000 处命中，超过时明确显示“+”及展示上限，不把部分数量冒充完整统计。Word、Excel 导出仍保存完整正文。

## 三、权限矩阵

| 对象或角色 | 可用范围 | 不能简单推断的能力 |
| --- | --- | --- |
| 个人空间 | 本人的目录和文件，依原所有权规则管理 | 不提供用户/机构授权入口 |
| 项目空间 | 按审计项目、小组、角色及 user_permissions 展示操作 | 不创建公共目录式的项目授权；成员角色仍由项目管理维护 |
| 项目/小组节点 | 有相应角色可创建下级、引入；项目节点可看审计小组 | 节点本身不能直接上传、重命名或删除 |
| 年度/单位节点 | 用于组织项目路径 | 不提供创建、上传、重命名、删除等资料操作 |
| 公共目录 READ | 查看、下载和选入检索/分析，依具体文件能力进一步控制 | 查看不等于可上传、删除或授权 |
| 公共目录 FULL | 可管理资料、新建下级 | FULL 不等于可以删除被授权目录，也不等于可分权 |
| 公共目录 FULL + can_delegate | 可新增/撤销目录授权；用户或机构；查看或管理；管理可附加分权 | 系统内置和未分配授权目录仍受原管理员条件限制 |
| 受授权的非创建者 | 按有效权限操作目录内资料 | 不因此取得被授权目录的重命名、删除所有权 |
| 文件上传者 | 保留原代码中本人文件的重命名、删除例外 | 所有权不解除引用/OSS 的只读约束，也不自动获得目录授权能力 |
| 文件夹创建者或管理员 | 按原目录权限和角色管理文件 | 不将“可以创建子目录”推断成可删除其他人的目录 |
| 引用目录 | 查看、检索、分析；具有 REMOVE_REF_FOLDER 时可取消引入 | 不上传、重命名、删除源资料；取消引入不删源文件 |
| OSS/归档文件 | 查看、下载、检索、分析 | 不重命名、删除、移动或修改附件；子目录不能用自己的 FULL 覆盖祖先只读来源 |
| 绑定项目 | 仅公共目录，按创建者、管理员与内置目录规则 | 不在项目/个人目录提供绑定入口 |
| 绑定机构 | 公共目录的超级文件管理员 | 不将机构绑定权限开放给普通可分权用户 |

界面新增“权限与访问”，展示当前目录允许与不允许的操作。项目目录明确说明角色权限来源。公共目录只有可分权管理者能查看授权对象列表并管理授权；普通查看者不展示其他用户的授权记录。

授权按对象 ID 选择，不用自由输入的姓名当身份。记录保留授权对象类型、权限级别、可分权、机构下级范围、授权人与时间；撤销需要确认；继承记录不能直接在下级撤销。新增授权、撤销、预览、下载、文件修改、附件写入、检索及导出均会在操作时重新检查条件。

**原代码的一个前端缺口：** 主资料页引用 `AttachmentListDialog` 时没有传入其已支持的 readonly 属性。因此，仅照搬弹窗按钮会把附件写入入口开放给只读资料。本次在界面与回调中限制引用、OSS 和非管理权限的附件写入；上线需要确认现有附件接口也执行对应授权，不能只依赖禁用按钮。

## 四、原代码依据与后台衔接

- `Index.vue` 6094–6154：引用、OSS、项目固定节点的上传限制。
- 6235–6458：目录菜单、创建、重命名、删除、分权、项目绑定与机构绑定。
- 7906–7984：文件上传者、目录所有者、管理员和 OSS 的文件操作规则。
- 1334–1477、8478–8520：授权对象、查看/管理、可分权、机构下级范围与授权请求字段。
- 2250–2257 与 `components/AttachmentListDialog.vue`：附件弹窗调用与 readonly 能力。
- 2530–2700：进入检索、选择资料、清空资料与清空结果。
- 2700–2827：完整正文批量读取、Excel 与逐文件 Word ZIP 导出。
- 2829–3050：服务端正则预匹配、上下键切换、正文及安全高亮。

生产衔接沿用已有服务：

1. `textSearchCheckFilesAPI({file_ids, pattern})` 做正则预匹配，使用现有内容接口读取正文；普通关键词先转义为字面模式。大小写选项不能未经确认向原接口新增字段：若现有正则引擎没有对应能力，可用原 `getFilesContentBatchAPI` 按最多 100 份批次读取已授权正文，由前端匹配，不新增后台协议。
2. 授权沿用 `grantee_id / grantee_type / permission_type / can_delegate / include_org_descendants`，授权对象实际应来自原用户搜索和组织树。当前站点的选择项用于验证交互，尚未连接真实组织服务。
3. 权限判断保持 `permission / user_permissions / is_creator / is_super_admin / can_delegate / is_system_builtin / is_granted_to_user / node_type / source / is_reference` 的语义；下载、分析等后端给出的明确禁用能力也应保留。
4. 项目首页当前对应一个项目节点，“园区改造项目”用于说明业务位置；实际接入必须使用真实项目及文件夹 ID，不把中文路径作为授权凭据，也不额外请求全空间文件来改变原根节点查询规则。
5. 真实权限必须由后台再次执行。独立站点的本地权限对象及按钮状态不具备身份认证或服务端授权能力；不将修改浏览器状态当成真实授权成功。

原始 Vue 前端 192 个文件未修改；没有改后端，也未连接内网授权、OCR、组织或项目服务。

## 五、验证结果

- `browser_search_authority_v6.py`：10 组专项交互，覆盖入口、范围、取消、正文高亮、完整内容导出、精确带入分析、授权和撤销、权限变化、四种屏宽。
- `browser_authority_edges_v6.py`：6 组边界验证，其中直接载入原源码权限函数，与新规则在空间、角色、管理权限、创建者/受授权者等组合下对比；另验证零宽正则、耗时表达式退出、长正文分段、多份 DOCX、引用只读及上传者例外。
- 更新并通过资料管理原有 14 组回归；授权场景改为公共空间，项目上传改为实际资料目录。
- 通过 11 项工具的添加资料及历史任务保留回归，以及文档解析、模板、配置、六类费用等既有回归。

结果与截图在 `review/v6-*.json`、`review/v6-*.png`。这些验证说明当前独立界面的行为；生产权限生效、组织数据、实际正则引擎及历史版本仍需用既有服务联调。
