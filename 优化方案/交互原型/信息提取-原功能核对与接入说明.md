# 信息提取：原功能核对与交互调整

核对日期：2026-10-19。原始 `前端代码` 和服务接口未修改；实现位于 `dist/extraction-workflow.js`、`dist/extraction-focus.js` 与同名 CSS，沿用资料管理的上传、权限、文件预览和模板模块。

## 1. 核对依据与定位

- `前端代码/views/file-manager-code/OcrViewer.vue`：文件/文件夹预览、附件合并、字段配置、模板、全局配置快照、执行弹窗、BatchExecuteByFilter 请求及四种格式导出。
- `前端代码/views/file-manager-code/components/OcrLeftSidebar.vue`、`OcrFolderPreviewPanel.vue`、`OcrBatchSettingsDialog.vue`：本次资料、目录勾选、批量设置、移出/恢复和目录预览。
- `前端代码/views/file-manager-code/components/AttachmentListDialog.vue` 与 `AttachmentSelectDialog.vue`：附件预览、添加、移除。
- `前端代码/views/ocr-task-center/TaskResultViewer.vue`：历史结果、任务参数、`final_result.items`、联合表、证据及置信度字段。
- `前端代码/views/file-manager-code/composables/buildToolBatchExecutePayload.js`、`前端代码/api/task.js`、`前端代码/api/template.js`：既有请求与数据契约。
- `界面截图/文件夹展示页面.png`：信息提取原工作区，左资料、中原件预览、右提取规则。
- `界面截图/文档资料挖掘-文件展示.png`、`选择文件页面.png` 及本会话截图：共用资料管理和资料选择风格。

工具目标：把审计资料中所需的要素整理为结构化信息，并能回到原件和证据核验。信息提取完成不等同于审计事实已确认，也不等同于文件刚完成解析。

| 选文件预览不改变执行范围 | 左目录切换中间原件，可切换解析内容或放大双栏对照 | 左侧明确全部资料参与；查找只过滤视野 |

| 附件查看、关联、移除 | 中间当前文件“附件”，右侧“附件与提取设置”中的管理入口 | 沿用既有附件选择与双栏预览；解除关联保留原件 |
| 主文件合并附件提取 | 右侧明确开关，默认不合并 | 开启才合并；结果证据可标明来自附件并打开对应原件 |
| 切片与冗余参数 | 右侧“附件与提取设置”，默认12000/200 | 切片1000–50000，冗余0–5000且小于切片；正式上限应读原数据字典 |
| 命名、备注、立即/后台执行 | 顶部“开始提取” → 紧凑执行弹窗 | 对应 task_switch 1/2；单次确认提交；配置与范围留存快照 |
| 执行进度、离开后查看 | 中间逐文件进度及顶部任务中心 | 后台提交进入任务中心；重新打开可看同一任务 |
| 失败/部分失败/停止 | 明确状态、保留成功结果、重试失败、停止确认 | 任务与源资料保留；复制新建不改旧任务 |
| 汇总表与逐文件结果 | 提取结果汇总，文件名/提取值/“核对原文”打开核验 | 宽表独立横向滚动，分页固定，成功数与缺失字段数分开 |
| 字段值、证据、置信度 | 原件与提取字段双栏，右侧切换解析内容、证据定位 | 有证据才展示；不重复证据块，不把“取到值”标成“准确”；未返回置信度时不补造百分数 |
| 原文定位/原件控制 | 证据在解析正文精确高亮；左原件保留翻页、缩放、下载 | 当前实现不伪造PDF坐标。正式PDF/DOCX精确定位继续复用原定位服务 |
| 结果 Excel/CSV/Markdown/JSON 导出 | 顶部“导出”，支持全部、所选、指定文件 | Excel含汇总、字段证据、任务配置三个表；CSV/MD含证据明细；JSON保留完整配置 |
| 多选与跨页导出 | 表头“本页”，跨页保留；选满一页后可选全部筛选结果 | 导出范围独立于屏幕筛选；导出时再次检查下载权限 |
| 历史配置只读与复用 | 结果页“本次配置”“复制新建” | 历史配置、停止任务配置均为快照，不直接编辑 |
| 文件权限与处理资格 | 使用资料管理的 read/preview/analyze/download 权限判断 | 执行前重查；解析未完成/无分析权文件不能提交；证据来源不可访问时不展示其取值 |

### 源码中保留但当前界面未开放的分支

原代码存在 `mode:'prompt'` 的请求分支，但当前 `OcrViewer` 的可见配置面板和批量设置以字段模式为主。本次以可见界面为准，不再把一个独立“提示词编辑器”展示成字段模式额外生效的参数。可配置的提取口径明确放在字段说明中。后续如需开放自由提示词提取，可沿用原 `custom_config.mode='prompt'` / `prompt` 分支，并为自由结构输出单独定义结果视图。

原目录批量选集支持后端展开文件夹；当前独立前端使用已加载资料将目录选择解析为文件集合。接入真实目录分页时应继续用原 `buildToolBatchExecutePayload` 的 `folders/checked_tree`、排除项和后端展开机制，不将前端已加载页误当整个目录。

## 3. 布局与操作原则

- 无全局面包屑/标题占位；信息提取业务操作栏常态56px，低矮窗口48px。
- 左：Step 1 添加资料；中：Step 2 核对原文、进度或结果；右：Step 3 配置提取字段，直接编辑全部字段。结果默认收起配置，给汇总表更多空间。
- “添加资料”在左侧固定可达，包括历史任务场景；历史任务添加资料确认后复制新建。
- 主操作按流程在右上角：开始提取；执行中停止；完成后本次配置、复制新建、导出。
- 模板管理操作集中到独立“提取模板”页面；任务名称和执行方式在提交前集中填写，减少右侧重复表单。
- 本次字段直接生效并持久化，名称和说明为16px；模板编辑仍需明确保存。列表中的全部字段参与提取，不需要的字段可移除并撤销；原模板不覆盖。切换模板前确认替换；历史字段只读。
- 目录、原文、字段独立滚动；桌面两侧均368px，1200px以内均320px；900px以内使用资料/原文/字段三面板切换，保留16px输入和单行主操作。修改字段、查找目录及勾选资料时保留PDF/Word视图，避免预览重载。

## 4. 既有服务接入映射

| 操作 | 原接口/函数 | 本次前端对齐 |
| --- | --- | --- |
| 创建/提交提取任务 | POST `/api/v1/task/BatchExecuteByFilter` | `biz_type:'fileToPdf'`；task_name、task_notes、task_switch；files/目录选集 |
| 模板模式 | `buildExecConfigBySettings` | exec_mode:'template'、template_id；custom_config包含merge_attachments、chunk_size、overlap |
| 自定义字段模式 | 同上 | exec_mode:'custom'；custom_config.mode:'field'、fields:[{name,description}]；同样保留三项执行参数 |
| 任务列表与运行态 | PageList、GetTaskSchedules、runtime | 保留原任务中心及轮询，不另建服务协议 |
| 结果详情 | GetTaskResultDetail | disposal_result → final_result.items；兼容 name/fieldName、extracted/value/fieldValue、is_found、evidence/evidence_list、chunk_id、notes、confidence |
| 联合结果表 | disposal_result.joint_table | 按文件名对应行，不把首行错误地回填到其他文件 |
| 终止与重试 | DeleteTaskSchedules、RetryFailedResults | 保留原终止/重试语义；成功结果仍留存 |
| 配置与模板 | 既有 template 接口 | 名称、描述、JSON字段规则；本地分类ID映射真实目录ID |
| 原件及定位 | previewFileAPI/getPreviewFileAPI、DirectPDFStyleLocatorService | 复用原原件地址与定位服务；附件沿用已有关系接口 |

`ewExecConfig` 已修正此前诊断片段中的 `chunk_overlap`，按原请求发送 **overlap**。`ewExecutionPayload` 是可检查的逐文件请求映射；目录正式接入仍复用原选集构建函数。仅在已映射真实后端模板ID且字段快照指纹（backendTemplateFields）一致的情况下使用 template 模式；本地模板ID不能直接当服务端 template_id。

## 5. 实现边界与验证

此站仍为独立的高保真交互实现，当前执行、进度与重试在浏览器中完成，没有接入内部模型/调度服务。文件上传、原件预览和下载为实际文件操作；提取的本地匹配只用于交互验证：只支持通用要素及明确标注的字段，不能替代真实模型的语义提取。不能取得的值显示“未提取到”。

正式接入需替换本地执行驱动为原服务，使用真实文件/模板/目录ID、服务端权限、原并发和字典配置、运行态与结果详情。保留现有后端的大逻辑即可；不能把本地任务计时器或示意的逐文件进度当真实服务进度。

验证文件：

- `tests/browser_extraction_workflow.py`：资料入口/移除、字段与参数、立即/后台执行、失败重试/停止、原件核验、导出、分页与低分辨率。
- `tests/browser_extraction_edges.py`：历史附件快照、权限变化、老任务配置保护与iframe嵌入。
- `tests/browser_extraction_templates.py`：完整模板流程及信息提取联动。
- `tests/browser_config_regression.py`：模板复用及词云、会议、两表规则回归。
- `review/extract-workflow-checks.json`：本轮验证结果；同目录PNG为四种尺寸截图。


## 6. 本轮原文与字段同屏调整（2026-10-19）

原源码 `OcrViewer.vue` 的 PDF 原件预览和右侧 `batchSettingsFieldMap` 内联编辑，支持审计人员边读资料边确定提取口径；`applyGlobalExtractSettings` 在执行前把这一套字段同步到全部目标。本轮恢复这一工作顺序，取消中央重复资料清单和“点文件先打开遮挡字段的大弹窗”的默认动作。

原件使用同一套真实文件查看器，支持PDF页码/缩放、Word、Excel、文本及媒体；原件不可用时明确提示，不能拿解析文本冒充原件。原文件刷新、下载收在预览区更多，放大入口仍提供原件/解析内容双栏对照。

字段顺序就是输出顺序；字段列表即本次提取范围，移除字段会同步更新本次配置；`ewExecConfig` 发送列表中全部 `{name,description}`。旧版勾选草稿按原实际执行字段迁移，不改历史快照。既有 `BatchExecuteByFilter`、附件合并、切片/冗余、任务命名、备注、立即/后台、停止/重试和四格式结果导出保持原契约。历史任务按实际执行字段只读展示，不因后续模板变化而改写。

验证：`tests/browser_extraction_focus.py` 及 `review/extract-focus-checks.json`；最新准备页截图为 `review/extract-focus-1440.png`、`extract-focus-1024.png`、`extract-focus-390.png`。原整链路、附件边界、模板联动、公共UI核对继续回归。

## 默认入口恢复（2026-10-19）
