# 完整业务流程：优化设计与源码核对

更新日期：2026-10-24。规范见 [33 · 完整业务流程与连续核验](../UI界面规范/33-完整业务流程与连续核验规范.md)，调研依据见 [产品操作模式对照](../产品调研/非结构化文档分析工具-操作模式对照.md)。

## 设计落地

日常路径统一为“选择本次资料 → 确认分析内容并执行 → 当前工具看成果 → 按需核验 → 导出”。复用现有资料空间、模板和提示词管理，保留11种工具的业务成果。后续布局按[通用工具原文工作区](通用工具原文工作区-设计与源码核对.md)修订：信息提取及六项通用/费用工具准备页三栏，四项复杂配置工具准备页两栏。没有增加后台工作流接口或要求每次创建新空间。

| 模块 | 解决的问题 | 实现与边界 |
| --- | --- | --- |
| `business-flow.js/css` | 准备和提交阶段不清楚本次处理什么、得到什么 | 统一业务标题与简短成果说明；提交摘要从真实字段、规则、阶段、分组、角色和映射读取。原任务参数及执行算法不变 |
| `material-reuse.js/css` | 需要重复找文件；从资料库进入可能覆盖已有准备草稿 | 在原选择弹窗中从分析记录勾选主文件，取消回滚；库带入默认合并保留已有设置/角色，替换明确选择；两表显式指定角色 |
| `integrated-evidence.js/css` | 合同和招投标检查详情与原文分开，核验多条时反复进出 | 复用source原件渲染器，承接完整原详情与证据内容，按当前筛选连续前后切换，关闭恢复原列表；权限和来源范围保持 |
| `review-notes.js/css` | 查看过结果无法独立记录人工核对情况 | 详情内可选“已核对 / 存疑”和说明，独立本地存储，按任务/身份/结果指纹隔离，不修改原AI结果；可单条导出核验记录 |

## 对照原有功能

原Vue的资料与模板配置、逐工具请求构造、会议阶段依赖、费用提取后续算、工程两类比较与两表角色都继续沿现有结构承接。本轮没有把它们合成统一的通用算法，也没有为显示处理链路重写任务状态。

信息提取继续使用 `ewResults()`、`ewReviewMarkup()` 和原前后文件操作。合同完整字段、依据、标准、建议来自 `cw-result-detail`；招投标内容来自 `bua-detail`、`bua-evidence`，保留双文件对比、证据范围与元数据。会议时间轴和议题聚类不改成通用表。

原结果页“调整后再分析 / 导出”、工具内分析记录、任务中心“查看结果 / 任务信息 / 导出数据”保留。原执行模式1/2与页面去向继续分离；费用基数和会议后续分析仍在当前工具承接。

## 权限与历史

文件及引用源逐级校验阅读、分析、解析和格式能力，明确过滤无法带入的资料。原分析配置和历史附件不随“选文件”复制；精确复用由调整后再分析完成。准备草稿的合并/替换不会改历史任务。

核验视图沿原 `cwReadable()`、`buaReadable()` 与 `auditFileAccess()` 检查所有来源。保存意见和导出意见也重查权限。人工记录独立于task/result/config；结果内容或核验身份变化后不会错误继承旧标记。

## 验证

- `tests/browser_business_flow.py`：11工具真实范围与成果、三类提交、执行方式保留、取消不改草稿、纯文本转义、三尺寸。
- `tests/browser_material_reuse.py`：暂存沿用、取消、解析/格式/权限/引用过滤、草稿合并与替换、招投标角色、两表显式指定及三尺寸。
- `tests/browser_integrated_evidence.py`：完整依据、多文件证据、当前筛选跨页连续核验、来源与解析切换、失权封闭、恢复原位置、历史不变及三尺寸。
- `tests/browser_review_notes.py`：意见独立保存、刷新恢复、身份和结果指纹隔离、权限重查、导出与三尺寸。
- 原准备页、任务内记录、结果重新分析、合同和招投标专项继续回归。验收证据存放于 `review/` 对应checks文件。

## 正式接入边界

保持原后端接口与参数；业务处理链路是对既有流程的说明，没有虚构细分进度或预计耗时。当前AI执行与身份仍为原型演示，人工意见保存在当前浏览器。正式上线需将意见连接到真实身份、稳定结果ID与轻量保存服务。

局部重新运行某字段/规则、跨工具中间结果自动复用需要明确的后端版本和执行语义，本轮没有通过前端拼接冒充完整结果。用户仍可沿用已有输入调整后新建分析，保留原结果。

本轮仅发布既有Sites，不更新43.128.232.108服务器，不生成用户部署包。
