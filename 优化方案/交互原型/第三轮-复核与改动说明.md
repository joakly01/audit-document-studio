## 1. 结论与本次交付

保留原有11项工具及专业流程，以前端局部调整为主要实施路径。新版交互原型已压缩顶部，补齐第一版过度简化的配置，并统一编辑、取消、保存、任务快照与模板复用方式。原有业务源码没有修改，未连接生产后台。

核对方法：对提供的192个源码文件、117471行建立完整目录、控件/调用索引与SHA-256清单；针对11项工具逐项检查入口、配置、结果、载荷构建与接口定义。不是声称逐行人工审查全部代码，也不是对生产后台的验证。清单见 [source-inventory.json](review/source-inventory.json)。本轮结束时再次比较哈希，原文件均未改变。此前已分析的15张截图、3份会议纪要继续作为业务背景。

### 布局

- 顶栏42px；在1366×768、1280×720、1024×768下，工作区从页面第120px开始。准备页主操作位于视口内。
- 保留左侧本次资料、中间预览/结果、右侧分析设置。两表保持双资料槽和主配置区。
- 三栏独立滚动，执行区固定在资料栏底部；标题、步骤与说明压缩，不以缩小正文替代布局优化。
- 1366宽度保留导航名称；1024宽度收起导航文字，悬停可看名称。手机为顺序布局。
- 结果默认收起配置，优先展示输出；再次查看的是执行时配置快照。

### 配置与常规操作

- 提示词、规则、提取字段、比较列均可编辑；“保存并应用”在右、“取消”在左。编辑暂存，取消回滚。
- 普通用户可以修改本次提示词、另存个人版本。系统原件只读，不等于本次内容不能编辑。
- 切换整套方案前提示替换范围；个人模板保存完整配置；支持版本2配置JSON导入、导出和结构验证。
- 动态字段/规则采用可增删清单；不把业务需求固定成三个字段或几枚复选框。复杂参数在编辑面板中完整提供。
- 任务名称、备注和审计关注可填。审计关注记入备注，需要影响分析时用户同时调整提示词；没有新增后台“审计目标”实体。

## 3. 审计业务判断

国家审计准则要求取得相关、可靠且充分的证据，关注证据冲突，记录审计过程，并在工作底稿中衔接审计事项、程序、证据、发现及依据；证据不足时不应作出相应结论。对本工具的直接含义是：原文能追溯、分析范围可见、判断依据可查看，且“未提取到”不能被界面变成“事实不存在”。[审计署：《中华人民共和国国家审计准则》，第84–87、99、106–109、133条](https://www.audit.gov.cn/n11/n10165075/n10165124/c10176144/content.html)

ISSAI 100第44、50段进一步强调可理解的审计记录及对证据的评价。以下是据此作出的产品判断，不是准则对本产品的认证。[INTOSAI：ISSAI 100官方PDF](https://www.issai.org/wp-content/uploads/2024/10/ISSAI-100-EN.pdf)

| 审计环节 | 本工具能够支持什么 | 仍由审计人员/外围系统完成什么 |
| --- | --- | --- |
| 明确事项与资料范围 | 任务名称/备注、本次资料、附件、分析要求 | 审计实施方案、范围完整性确认 |
| 整理分散资料 | 提取、词频、主题、时间线、会议归类 | 资料真实性、完整性与可靠性评价 |
| 识别疑点 | 风险关注、合同/招投标规则、项目关系候选 | 法规/制度适用性、冲突证据调查、追加程序 |
| 核验线索 | 原文/源行、规则依据、历史配置、缺失标识 | 外部函证、访谈、现场检查等取证 |
| 形成结论 | 导出结构化结果与来源，作为底稿输入 | 事实确认、定性、责任、复核签署与正式底稿归档 |

设计可达成“辅助整理资料、发现和核验线索”的目标；不能独立闭合完整审计证据链。没有为此强行新增审批流、证据库和底稿后台。本轮先把本工具应承担的输入、过程、输出讲清楚。

业务验收建议采用现有虚构例子：会议要求预算由120万调整至128万需先报批，合同金额128万。工具应帮助找到相关会议、合同与审批资料；缺少审批材料时输出待核验线索，不能直接输出“违规超预算”的确定结论。正式模型能否做到，要用脱敏真实案例另行评测。

## 4. 少改后端的实施边界

1. **纯前端先行**：紧凑布局、步骤提示、统一编辑器、折叠参数、输入校验、结果筛选、模板应用确认。
2. **接现有API**：复用文件、任务、提示词、词库、报告、费用继续执行、两表二次分析接口，保留各工具现有builder及结果解析。
3. **不新增业务字段**：审计关注合入已有task_notes；提示词仍写入对应阶段。schemaVersion只用于前端配置导入迁移，不能直接塞进后台请求。
4. **出站配置必须适配**：阶段名称映射真实模板ID/key；合同类别与费用类型映射原枚举；招投标保留bidding_only/tender_only/joint_only；会议百分比换算；工程/两表沿用原规范化函数。
5. **未知配置保留**：生产中编辑配置应从后台原对象深拷贝后只更新已编辑字段，保留veto_rules、arbitration等未展示结构及派生逻辑。原型的configurationFragment仅是字段核对片段，不是完整可直接提交的请求。
6. **提交和权限以服务为准**：不把计时器当完成，不把前端可见当授权；失败保留输入，历史任务只读，修改需复制新建。长任务、停止/重试范围、并发与文件权限须真实联调。

## 5. 可扩展性与实现范围

- `config-schema.js`集中定义阶段、费用类型、比较类型及配置迁移；新增模板/字段/规则不要求修改页面布局。
- `design-v2.js`提供编辑器、配置快照、模板导入导出与核验上下文；暂时以扩展层保留第一版路由及结果实现。回迁Vue时拆入原有组件，不建议把全局覆盖结构用于生产。
- 个人模板保存阶段内容和结构化参数，系统原件保持只读；后台ID、权限、版本号以真实服务为准。用户能配置规则，不等于能凭模板新增后台尚不支持的算法。
- 词库支持文本及本原型JSON；模板导入只支持版本2。正则为有限语法，明确展示限制，生产可以复用原正则服务或放入可中止Worker执行。
- 所有结果为虚构示例；提示词、权重、硬规则、锁定、切片等主要用于配置与快照演示，未接模型重新计算。工程阈值、结果筛选等简单演示规则有效。六费用类型均可配置，但其他类型尚无可计算样例。
