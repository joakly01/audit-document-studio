# 招投标分析：规则工作区与源码核对

更新日期：2026-10-23。发布到现有 Sites，按用户要求暂停服务器更新和交付包生成。

## 原前端的业务关系

核对 `前端代码/views/DemoAudit/bidding-analysis/BiddingAnalysis.vue`、`components/BiddingAnalysisRulePromptPanel.vue`、`utils/biddingAnalysisPromptConfig.js`、`mock/biddingAnalysisTemplateMock.js` 和结果查看组件。

1. 一个项目包含1份招标文件、多个投标单位及各单位多份投标文件。招标文件选择为单选替换，投标文件可多选；保留人工配置文件角色，不能仅凭文件名认定归属。
2. 三种模式可以组合执行，分别选择自己的提示词。原模式映射为：界面内部 `tender → bidding_only`、`bid → tender_only`、`joint → joint_only`，不可把两个英文命名直接对调。
3. 所选提示词的配置决定当前模式的全部规则。原组件将规则作为说明标签展示，没有独立勾选规则、逐规则另行编辑的交互；本次沿用这一执行关系。调整检查要求通过提示词编辑，保存个人提示词时保留配套规则。
4. 仅有空项目占位时，不应阻塞其他已配置项目；有文件的项目必须符合已选模式要求。招标或联合模式需招标文件，投标或联合模式需至少一家有投标文件的单位，单位名称需填写。
5. `buildCreatePayload` 每种模式分别保留 `template_id / prompt_id / prompt_text / prompt_customized / rule_ids`，再提交项目、招标文件及各投标单位文件；结果按项目、单位和规则查看并回溯来源。

截图中的规则比源码 Mock 默认集合多，实际应以提示词配置返回的清单为准。静态原型默认按源码的7条招标、1条投标、7条联合规则演示；不臆造截图中未给出的规则ID。个人提示词或接入配置包含更长列表时完整保留，不以默认条数截断。

## 本次界面

- 两栏：左侧“Step 1 配置项目资料”，右侧“Step 2 设置分析内容”。取消中间常驻原文区域及原文自动加载；点文件名仍可同时查看原始文件、解析内容。
- 左侧直接选择项目、新增项目，填写项目名、选择或替换招标文件，新增单位及维护各单位标书；不再必须进入“管理项目与单位”弹窗。
- 多个项目用当前项目选择框切换，保留全部项目配置；单位超过10家分页，文件默认限量显示并可展开，查找单位或文件不改变参与范围。资料管理传入的未归组文件继续显示待分配列表。
- 右侧每种分析模式采用一张紧凑卡片：勾选决定是否执行，“查看规则”决定正在浏览的提示词和规则。取消重复的下方模式页签，两种操作相互独立；不能取消最后一种模式。
- 提示词选择、来源及“编辑提示词”保持紧凑。公共 / 机构 / 个人分类、系统默认选择、另存个人提示词和切换配套规则的确认继续复用。
- 规则以表格展示名称和检查重点，支持搜索、20 / 50 / 100条分页、查看完整说明及规则编号。明确提示“本次执行此提示词的全部规则”；检索和翻页不改变实际执行规则。
- 小屏切换项目资料与分析内容；低高度压缩顶部和辅助说明，规则表格独立滚动，分页固定可达。任务信息沿用同一规则浏览方式，只读查看执行快照。
- 移除资料后的撤销同时恢复项目、单位、文件角色、待归组清单及当前预览，不只恢复文件数量。

## 从分析结果查找待核验事项

结果区分“检查结果 / 分析资料 / 分析报告”。审计人员先按项目、分析环节、核验状态、实际返回的风险等级及关键词筛选，再打开“查看详情”阅读判断与建议，或从“查看证据”核对相关招标、投标及附件原文。清单支持20 / 50 / 100条分页，筛选不删改原始结果。

保留原结果中的 `aiAnalysisItems` 判断依据、合理性说明、建议、证据与文件提取信息；联合检查可回溯多个文件，不能用单个文件替代对比证据。文件UUID优先，按名称回溯时处理同名文件歧义。任何一个必要来源无权限、已删除或不在本次任务内时，该条结果不进入展示与导出。

“分析资料”保留原件与解析正文预览及实际返回的结构化信息；“分析报告”按本次结果整理。表格导出使用业务列名，JSON保留原始结果结构、执行配置及关联，报告与导出不重新运行任务。旧记录没有返回的规则编号、环节、风险等级明确显示未提供，不从摘要编造判断。

## 验证与接入边界

`tests/browser_bidding_workflow.py` 覆盖项目、单位、角色文件增改，空项目和不完整项目校验，三模式，招标单选与取消，原文双栏预览，1000条配套规则的检索分页、切换确认及执行快照，历史只读和调整后再分析，以及1366×768、1024×480、390×600布局。

`tests/browser_bidding_audit.py` 覆盖103条混合结果、项目/环节/状态筛选、判断详情、多来源证据、来源权限、同名文件、原始数据导出、历史任务不变及多尺寸结果页。通用 `browser_prompt_guidance.py`、`browser_prompt_tool_execution.py` 继续检查个人提示词、模式隔离、跨工具执行和结果入口；“调整后再分析”沿用既有独立草稿能力。

原型的 `configurationFragment('bidding', config)` 现在对齐原前端 `analysis_modes / mode_configs / projects` 的字段结构并保存为任务快照；静态数据中的文件ID仍为本地演示ID。正式服务、提示词树权限、项目名自动提取、后台阶段轮询和规则级AI结果需继续按原接口联调，本次没有伪造正式服务调用或改写原 Vue 源码。
