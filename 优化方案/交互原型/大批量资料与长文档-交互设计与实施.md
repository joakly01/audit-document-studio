# 大批量资料与长文档：交互设计与实施

日期：2026-10-21。适用：资料管理、信息提取、通用分析与审计专题工具、任务中心。

## 设计判断

现有三栏结构能够继续沿用。下一步重点不是再增加一层流程，而是让用户始终知道：**本次处理哪些资料、当前看到哪里、处理到了哪一步、哪些结果需要自己核对。**

文件数量、单个文件长度、配置项数量、结果数量是四个不同的负载，不能只用“文件总数”判断复杂度。10份长合同可能比数百份短单据更难核对；两张台账的工作量还取决于行数、字段及比较上限。显示分段也不能改变实际执行范围。

## 沿业务流程检查

| 环节 | 大量资料下的实际问题 | 交互约定 |
| --- | --- | --- |
| 选择资料 | 分不清本页、全部页、其他目录已选 | 保留已有“本页／全部页”及跨目录数量；搜索不清空原选择；提交前按当前权限、解析状态和类型复核 |
| 已添加资料 | 几百份文件一长串，滚动后找不到当前原文 | 超过50份分页显示；文件名或目录查找；定位当前预览文件；全量执行数量始终保留 |
| 预览核对 | 长正文滚动成本高，来回切文件丢失位置 | PDF保留页码跳转；解析文本按阅读段展示、全文查找、逐处定位；各文件保留阅读位置 |
| 配置要求 | 字段／规则数量多时难以判断适用范围 | 保持当前规则与字段编辑；清楚说明应用到全部本次资料；个人模板继续复用；不同工具保留独立规则结构 |
| 提交分析 | 用户担心漏文件、重复提交、必须守在页面 | 保留命名、配置快照、资料范围和后台查看入口；不得用“当前显示50份”替代全部执行IDs |
| 查看任务 | 只知道部分失败，不知道具体是哪些文件 | 任务资料支持文件／目录查找与分析状态筛选；大清单分页；成功、失败、尚未返回结果、终止后未处理明确区分 |
| 核对结果 | 结果行数与文件数混淆，误认AI结果为审计结论 | 沿用工具专有结果页面、来源定位、已有结果保留和失败重试；保留文件数、结果条数各自单位 |
| 导出 | 用户担心只导出可见页 | 导出依旧使用完整的任务结果与导出配置；分页及阅读分段只影响查看 |

## 本轮已实施

### 1. 已添加资料清单

- 信息提取及普通多文件分析工作区，每页最多显示50份文件。目录仍按空间与原目录展示，不修改文件归属。
- 分页在左侧清单底部，仅当文件较多或正在查找时出现。小规模场景维持简洁。
- 支持页码跳转、“定位当前”；定位操作清除当前查找、展开当前文件的上级目录，并滚动到该文件。
- 分页不自动切换中间原文，阅读不会因为翻页中断。查找时临时展开匹配目录，清空查找后保留用户原来的折叠设置。
- 清单当前页与执行范围分离：执行仍使用全部主文件IDs；移出和撤销保持原顺序；附件仍独立关联。
- 招投标保留项目、招标资料、投标单位分组，分页只限制本页展示的文件；项目／单位管理仍使用完整分组。两表关联固定两张表，不套用多文件分页。
- 优化资料ID查找，避免取出大批量已选资料时逐项遍历整个资料库。

### 2. 长解析正文阅读

- 正文超过12,000字符时按约6,000字符划分阅读段，尽量在换行处切分；不是原文件页码，也不是AI处理切片。
- 明确提示“全文参与分析 · 分段仅便于阅读”，原有切片参数及导出全文保留。
- 查找覆盖整篇解析正文，支持中文、英文字母及特殊符号的字面匹配；回车或点击“查找”执行，输入期间不刷新正文。
- 显示匹配数量，支持前一处／后一处并跳到对应阅读段；跨阅读段的匹配也能查到。
- 当前访问期间记忆每份文件的阅读段、查找条件、滚动位置；原文件PDF页码／缩放、表格工作表／页码亦按文件记忆。
- 阅读缓存有上限，正文不写入新的浏览器持久化副本。修改配置仍保持已加载的原文件预览会话。
- 无预览权限时不展示正文；原件与解析内容仍分别展示。原始Word、PDF和表格的既有预览与下载保持。

### 3. 任务资料定位

- “任务信息 → 分析资料”增加文件名称／目录查询、工具分析状态筛选和分页。
- 状态按该任务的成功／失败IDs判断，未返回结果不会被推断成成功，也不误写成“未解析”。
- 终止任务中的未完成资料显示“未处理”；已有分析成功和失败记录仍保留。
- 查看原文再关闭，可回到同一任务资料清单，保留查询、状态和页码。
- 已失去查看权限的原资料，不继续显示其文件名及路径；任务计数仍保留执行范围。

## 分工具保留的业务差异

| 工具 | 必须保留的工作单位和逻辑 |
| --- | --- |
| 信息提取 | 文件 × 提取字段；字段顺序、模板默认空、个人模板、附件合并、原分段设置 |
| 词云 | 选中资料范围、停用词／用户新词、展示词数、词频及来源；词数不是处理文件数 |
| 会议纪要 | 会议与议题、风险报告、进一步问答；不同结果之间保留原文来源 |
| 风险点 | 文件 × 检查点；按文件／按风险点遍历；未匹配线索与证据不足分开 |
| 时间轴 | 事项与原文日期；缺日期事项单列，不用上传时间填补 |
| 主题归纳 | 基础信息提取、主题归纳两阶段；归纳失败保留基础信息，阶段重试不重复全部工作 |
| 合同 | 合同类别、检查规则、附件合并与自动分析设置；条款检查不是最终审计定性 |
| 招投标 | 项目、招标文件、投标单位、独立分析阶段；文件分组不能被普通文件分页打散为无归属清单 |
| 待摊费用 | 先提取计费约定，再填写基数并计算；第一阶段成功不等于费用报告完成 |
| 工程项目 | 重复项目／主子项目分别配置；字段映射、预筛、评分和原行证据 |
| 两表关联 | 表一／表二、业务名称、字段映射、硬规则、比较上限与锁定设置；两张表可能有大量行 |

## 生产接入需要继续落实的部分

这些是后端／文件服务接入要求，**本轮不把浏览器原型表现当作已经具备的生产能力**。

1. **服务端范围快照**：百万级资料库不能把所有文件记录拉到浏览器再“全选”。应保存空间、目录、搜索及权限条件快照，返回可选总量和排除项；提交时重新校验。当前独立前端仍使用已加载的IDs集合。
2. **执行队列与恢复**：限制并发、排队、幂等提交、进度订阅、离开页面后继续、刷新后重连需由任务服务支持。浏览器演示任务不具备服务端持久执行能力。
3. **真实进度**：分别返回排队／读取／解析／工具分析／归纳／导出阶段及成功失败数量。缺少总量时显示阶段和已处理数，不伪造百分比与预计剩余时间。
4. **大文件读取**：PDF可继续按页绘制，但当前原件加载仍可能读取整个文件；超大PDF需文件服务Range读取与按页文本索引。Word长文宜服务端转换为可分页格式。Excel现有分页限制DOM行数，工作簿解析仍可能整本载入，需要后端分页或工作线程进一步承担。
5. **长文检索与来源锚点**：当前全文查找针对已取得的解析文本。超长正文应由服务端按段返回，并提供全文检索、页码／段落／表格坐标，避免一次传完整正文。阅读段不冒充原件页码。
6. **大结果集**：按任务、文件、状态及业务字段服务端分页；导出由服务端独立任务完成，沿用已有字段映射和分文件规则。不能仅导出当前可见页。
7. **业务复杂度**：风险任务按文件与检查点、两表关联按候选对数等统计真实工作量。没有原始页数／字数／行数时标注未知，不能用文件大小猜时间。

## 验证边界与验收重点

采用浏览器临时生成的压力数据，未向用户资料库、默认样例或生产任务注入测试文件。

- 1,500份文件：分页、页码跳转、定位、中文查找、末页移出及撤销；执行IDs数量及顺序保持。
- 长正文：约84万字符、末尾匹配、特殊字符、中文输入、跨段匹配、切换文件恢复阅读段。
- 1,500份任务资料：75份失败记录筛选、翻页、名称查询、任务范围不变。
- 真实原文件：PDF页码／缩放记忆，已有PDF／Word／Excel预览及附件流程回归。
- 1366×768、1024×480嵌入高度、390×600窄屏：核心区独立滚动，不靠缩小字体容纳数据。
- 原有工具配置、执行、历史快照、结果路由、导出与中文输入回归。

以上是前端交互及浏览器压力验证，不是服务端AI吞吐量或最大支持规模承诺。详细结果见 `review/large-workloads-checks.json`。

## 已选资料入口收拢（2026-10-21）

资料库的选择汇总放在列表底部；工具本次处理的资料统一放在左侧清单，去掉顶部和右侧配置区的重复总数。添加资料弹窗的右侧为完整待确认清单，底部使用“确认选择”；取消不改变工具已有资料，确认后更新。当前页/全部页仍在表格上方操作，其他目录的已选项统一在完整清单中查看。附件与对照表保留各自业务语义，不与主资料选择混合。

资料计数、查找结果和显示页范围共用左侧底部摘要。手机端保留资料页签数量；提交时的范围核对与历史执行资料不删减。此调整不修改执行IDs、任务配置快照或服务请求契约。
