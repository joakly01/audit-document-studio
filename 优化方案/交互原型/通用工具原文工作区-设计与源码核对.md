# 通用工具原文工作区：设计与源码核对

更新日期：2026-10-24。详细规范见[34 · 通用工具原文工作区](../UI界面规范/34-通用工具原文工作区规范.md)。本轮修订31、33号中其他工具准备页默认两栏的口径，保留既有执行、权限及结果逻辑。

## 设计范围

词云、主题归纳、时间轴、风险点、会议纪要、待摊费用六项准备页统一为“Step 1资料—Step 2查看原文—Step 3分析设置”。原文默认显示，阅读按需进行，不设必读门槛。信息提取维持原三栏；合同、招投标、工程一致性及两表关联度维持两栏。

左右默认各320px，中间弹性；分隔条支持拖动、方向键、Home和双击恢复。移除原文收起／展开操作，并恢复旧的隐藏状态。步骤、文件名和原文／解析切换合并为一行；PDF翻页与缩放栏压紧。按实际容器宽度适配：不小于1000px为三栏，620–999px资料常驻并切换原文/设置，小于620px为三面板切换。提示词纵排，减少窄栏挤压。

## 源码承接

| 层次 | 本轮处理 | 保持的业务边界 |
| --- | --- | --- |
| `tool-preparation.js/css` | 六工具准备态布局、原文面板、容器断点、分隔条 | `tlPreparing()`仅作用于未进入任务结果的准备态 |
| `twMaterials()` / `pwMaterials()` | 继续使用原资料列表与操作 | 资料范围、附件、检索、移除和费用专有资料逻辑 |
| `configPanel()` / `tlBase.configPanel()` | 调整设置栏结构与步骤标题 | 原提示词选择、词库、风险点及逐工具配置控件 |
| `twMountPreview()` / `previewParsedMarkup()` | 复用原预览；解析文本按需生成并保留DOM，PDF适宽重绘 | 原文件/解析文本、页码缩放、独立展开预览及权限检查 |
| `tlCanPreview()` | 沿文件引用链检查read和preview | 无权限时不给原文或解析内容，已有分析配置不被改写 |
| `business-flow.js` | 与三步骤标题保持一致 | 提交摘要、实际文件及配置范围继续沿既有函数读取 |

当前文件通过`ws().preview`和`tv()`管理阅读状态，不是分析范围选择。面板宽度偏好保存在本地，不写入任务或后端配置；切换预览不减少参与分析的已选资料。

原Vue会议页`views/DemoAudit/meeting-minutes-analysis/index.vue`及`components/TimelineClusterSwitch.vue`中，中间区域承接会议时间轴、议题聚类等成果。时间轴页`views/DemoAudit/timeline-analysis/TimelineAnalysisViewer.vue`同样以事件时间轴为核心。本次准备态原文是操作一致性优化，结果态继续原业务展示，不将原文面板覆盖到时间轴或议题聚类上。

待摊费用仍保留计费约定提取、填写基数继续计算两阶段。提示词内容、执行方式、请求构造、历史任务快照、导出及结果复用未因布局新增后端要求。

## 对标依据

官方文档可核实的模式是：UiPath[原文与字段并列且可调宽](https://docs.uipath.com/activities/other/latest/document-understanding/compact-validation-station)、ABBYY[独立面板可隐藏/折叠](https://help.abbyy.com/en-us/vantage/1/developer/developer_integrate_manual_review/)、DataSnipper[单条结果与原文专注核验](https://knowledge.datasnipper.com/en/articles/714302-how-to-efficiently-review-answers-using-focus-mode)，以及Ant Design[多面板尺寸约束、折叠和双击恢复](https://ant.design/components/splitter/)。

据此，本项目采用“简单工具默认三栏，复杂配置维持两栏，结果核验专注单条”的组合。六工具范围、320px基准和容器断点属于本项目设计判断，不将其表述为行业统一规定，也没有引入新的组件库或后台流程。

## 验证

本轮已通过以下专项，执行证据见`review/`对应报告：

- `browser_tool_preparation.py`：六工具、18个尺寸场景；实际请求保持、行内原文、解析懒加载、阅读会话、原文放大返回后的页码/缩放、旧收起状态恢复、键盘调宽、权限及结果衔接。
- `browser_prepaid_workflow.py`：原有五组费用专项，包含六类费用、计费约定与同任务续算、元单位、多合同、原生输出、权限、导出及历史。
- `browser_business_flow.py`、`browser_material_reuse.py`、`browser_result_reanalysis.py`：提交摘要、资料沿用与草稿保护、11工具历史结果的独立再分析。

另做实际鼠标拖动、PDF适宽与翻页、双击恢复、点击文件阅读及陈旧按钮失权检查；有效引用文件自身仍有权限时，源文件失权也不能借旧按钮打开原文。专项未发现脚本错误或页面横向溢出。以上是前端原型验收，不代表正式AI后端联调。

按用户约定只更新既有Sites，不更新外部服务器，不生成用户部署包。

原文栏精简专项：步骤标题、文件名与切换合为44px单行，PDF翻页与缩放保留紧凑独立一行；信息提取、会议及风险点三尺寸未出现横向溢出，原件／解析切换及执行配置不变，详见 `review/source-toolbar-checks.json`。六项通用工具专项同时覆盖旧收起状态恢复与18个尺寸场景。
