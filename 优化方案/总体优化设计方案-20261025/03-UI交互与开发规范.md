# UI 交互与开发规范

> 审查日期：2026-10-25。适用基线：当前交互原型静态资源 `20261024.80`，源码提交 `2e7b0b29450609b156674e413364ee0d150cda74`。面向产品、设计、前端和测试，作为本轮统一交互规则与正式实施依据。
>
> **已实现**指原型存在相应交互；**已验证**仅覆盖列出的检查范围；**规范要求 / 待整改**是正式开发与验收要求。原型的浏览器验证不能替代真实后端、生产数据和真实审计人员的验收。

## 1. 整体审查结论

当前界面已形成稳定的操作骨架：添加本次资料，设置业务规则或提示词，提交后在当前工具查看进度与结果，再按需查看原文和导出。规则复杂的工具使用两栏，通用工具保留原文阅读区。一致性体现在动作位置和状态含义，不要求每种业务使用同一张表或相同栏数。

本轮重新启动本地静态预览，检查了 11 个工具的准备页，在 1366×768、1024×480、390×600 下共检查 33 个状态：未发现整页横向溢出、收起原文入口或脚本错误。任务中心首条任务行的操作为“查看结果 / 任务信息 / 导出数据”，均未附加图标。这是页面骨架和指定文案的检查，不代表所有弹窗、结果和权限组合已重新回归。

仍需处理的主要问题：

1. **后加辅助文字颜色偏浅。** 提示词说明、来源、规则提示和部分操作引导的实测对比度为 3.651–3.825:1，低于既定 4.5:1 要求。
2. **历史规范与当前产品存在冲突。** 旧主规范和设计变量仍保留“当前位置”“核对原文”、旧选择操作位置等内容，不能直接逐字移植。
3. **原型的分层覆盖实现需要在正式前端收敛。** 当前依赖多个后加载脚本覆盖工作区、文案和样式。正式开发应落到稳定组件、状态模型和按工具声明的配置，避免修一处后又被后续逻辑覆盖。

## 2. 规范效力与历史冲突收敛

执行顺序：用户最新确认 → 本轮总方案及本规范 → 当前有效专项规范 → 历史截图与过程说明。历史资料用于追溯，不应叠加成额外需求。遇到差异应记录评审结论，不能自行恢复旧入口。

| 历史表述 / 规则 | 本轮统一规则 | 实施含义 |
| --- | --- | --- |
| 当前位置 | **当前目录** | 路径包含有效空间、项目及目录层级 |
| Step 2 核对原文 | **Step 2 查看原文** | 按需查看，不是提交分析前的必做步骤 |
| 收起原文 / 展开原文 | **不提供这两个动作** | 桌面原文常驻；窄屏通过面板页签切换；恢复旧隐藏状态 |
| 调整后再分析 / 新建复制 | **再次分析** | 复用资料与配置进入编辑，确认后新建任务；不直接执行或覆盖历史 |
| 风险点“开始核查” | **开始分析** | 当前风险点主操作已统一 |
| 时间轴演示 | **不在正式工作区提供入口** | 会议时间轴能力保留，演示数据与业务按钮分开 |
| 回溯配置 / 下载结果；操作附图标 | **查看结果 / 任务信息 / 导出数据**，三个文字操作直接可见 | 不把核心操作藏在省略号中 |
| 工具内导入设置 / 导出设置 | **移除** | 不影响结果导出、词库导入导出、独立提取模板管理 |
| 所有工具固定三栏或默认两栏 | **按配置复杂度分两种布局** | 见第 3 节，不以统一为由抹掉工具差异 |
| 选择提示词 / 使用方案作为整栏标题 | **动宾结构 + 业务对象** | 不把一段提示词夸大为分析方案 |
| 全部页操作有时在表上、有时在表下 | **资料管理和资料选择器均放在表格上方** | 表头复选框仅选本页，范围与数量明确 |
| 仅本级 / 含子文件夹 / 同时显示子文件夹中的文件 | **包含下级文件夹**复选项 | 开启后含所有下级；说明放悬停和可访问提示 |
| 提取模板默认已选 / 模板（可选） | **初始不选模板、不预填字段；标题“提取模板”** | 选模板载入字段或自行添加；至少一个有效字段 |
| 上传下拉分别放文件、文件夹入口 | **一个“上传”入口** | 弹窗内部选择文件或文件夹 |
| 原文标题、文件名、页签多行堆叠 | **标题、名称、页签、放大入口合为一行** | PDF 翻页缩放另保留一条紧凑工具行 |

## 3. 页面骨架与工具差异

### 3.1 准备、运行、结果三种工作状态

**准备态**允许编辑资料范围和分析内容。默认进入工具显示当前可操作草稿，不自动跳入历史任务。当前预览文件、搜索结果与本次执行范围是三个不同集合。

**运行态**展示真实状态、范围与进度，提交配置只读。用户可离开页面并在记录中恢复。没有真实进度时显示等待更新，不使用前端倒计时生成假百分比。

**结果态**以工具成果为主体，不常驻准备页的资料清单。查看依据、筛选、导出和再次分析均针对当前结果；本次资料和完整配置集中在“任务信息”，不重复铺设配置按钮。

状态必须区分对象：**解析完成**表示资料已准备好；**分析完成**表示 AI 结果已返回；**已核对**表示人员做过核验。风险线索或候选关系不等于已认定审计问题。

### 3.2 准备页的最终标题

| 工具 | Step 1 | 原文阅读 | 配置标题 | 主要业务差异 |
| --- | --- | --- | --- | --- |
| 信息提取 | 添加资料 | Step 2 查看原文 | Step 3 设置提取字段 | 开始提取；模板与字段默认不预选 |
| 词云分析 | 添加资料 | Step 2 查看原文 | Step 3 设置统计规则 | 开始统计；停用词、新词、展示词数分别解释 |
| 主题归纳 | 添加资料 | Step 2 查看原文 | Step 3 设置主题归纳提示词 | 开始归纳；资料要点与主题归纳分阶段 |
| 时间轴分析 | 添加资料 | Step 2 查看原文 | Step 3 设置事项提取提示词 | 日期、事项与来源形成时间线 |
| 风险点分析 | 添加资料 | Step 2 查看原文 | Step 3 设置风险分析内容 | 包含提示词、风险点与检查方式 |
| 会议纪要分析 | 添加资料 | Step 2 查看原文 | Step 3 设置会议分析提示词 | 会议、议题聚类；后续风险与问答按需进行 |
| 待摊费用 | 添加合同 | Step 2 查看原文 | Step 3 设置计费要求 | 先提取约定，再填写基数计算费用 |
| 合同分析 | 添加合同 | 按需打开 | Step 2 设置检查规则 | 合同类别、规则与补充分析分清 |
| 招投标分析 | 添加项目资料 | 按需打开 | Step 2 设置检查内容 | 项目、招标文件、投标单位和文件角色明确 |
| 工程项目一致性 | 添加台账 | 按需打开 | Step 2 设置比较规则 | 表内重复与主子项目两类分析均保留 |
| 两表项目关联度 | 选择对照表 | 按需打开 | Step 2 设置关联规则 | 两表角色、字段映射、评分和硬规则明确 |

三栏统一位置，不意味着逐份阅读是运行前提。两栏工具把空间留给规则、角色和字段映射，原文仍可打开。结果页按成果组织，不能照搬准备页。

### 3.3 响应式与原文区域

通用三栏左右区域默认各 320px，中间使用剩余空间；实际宽度受容器约束，可拖动调节。不能把这一值直接套用到信息提取、招投标等独立布局。断点按嵌入后**实际工作区宽度**判断：

| 工作区可用宽度 | 通用三栏工具展示 |
| --- | --- |
| ≥1000px | 资料、原文、配置同时显示 |
| 620–999px | 左侧资料保持，右侧在原文与配置间切换 |
| <620px | 已选资料、查看原文、配置三个面板切换 |

面板切换保留选择、草稿、当前文件、页码、缩放和滚动。大表可以内部横向滚动，不能撑宽整页。不要把 16px 正文改成 12px 来制造紧凑。

原文准备区头部统一为 `Step 2 查看原文 | 文件名 | 原文件 / 解析文本 | 放大查看`。当前测量头部 44px，PDF 翻页缩放行约 39px，合计约 83px。这是该版本测量，不要求所有文件格式生搬相同高度。文件名可省略但需完整提示；小容器可隐藏 Step 2 英文编号，保留“查看原文”和内容切换。

## 4. 视觉设计变量与组件状态

以下为**规范目标**，不表示所有当前局部样式已采用。浅色辅助文字需按第 10 节整改。

| 变量 | 规范值 | 约束 |
| --- | --- | --- |
| 字体 | 微软雅黑、苹方、Noto Sans CJK SC、Arial、sans-serif | 不依赖单一系统字体的精确字宽 |
| 主体 / 输入 / 主按钮 | 16px；行高 1.5–1.6 | 业务可见文字最低 14px |
| 辅助、表头、来源、状态 | 14px；行高 1.6 | 辅助不等于低对比度 |
| 工具 / 密集区块标题 | 18px / 16px，字重 600 | 不重复增加欢迎区或大标题 |
| 弹窗标题 | 20px，字重 600；窄屏可 18px | 正文保持可读 |
| 解析正文 | 16px；行高 1.8–1.9 | 原件排版由预览器保持 |
| 页面 / 面板背景 | `#F4F6F9` / `#FFFFFF` | 避免卡片套卡片过深 |
| 正文 / 辅助字 | `#1E3046` / `#596B80` | 需在实际背景计算对比度 |
| 主色 / 浅主色 | `#3269DB` / `#EEF4FF` | 主任务、选中、链接使用 |
| 表头字 / 背景 | `#52657B` / `#F5F7FA` | 表头清楚但不抢结果主体 |
| 分隔 / 控件边框 | `#E6EBF1` / `#DCE3ED` | 控件边界应可辨认 |
| 成功状态 | `#1D735B` 字 + `#EAF7F2` 底 | 不代表审计认定 |
| 警示状态 | `#8A5A16` 字 + `#FFF5E5` 底 | 资料不足、需补充 |
| 失败状态 | `#A33E3E` 字 + `#FCEEEE` 底 | 配合原因和恢复入口 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px | 同类组件复用 |
| 常规按钮 / 输入框 | 高度 ≥36px | 命令栏常规 56px，低矮桌面 50px |
| 图标 / 点击区 | 图标 18–20px；独立目标 ≥24×24px | 文件行建议 30×32px；不能以小图标代替合理点击区 |
| 圆角 | 轻量操作 4px、控件 8px、面板 9px、弹窗 10px | 同一组件保持一致 |
| 动效 | 120–180ms，复杂展开 ≤200ms | 支持减少动态效果，不延迟主操作 |

同一任务区域原则上只有一个实心主按钮。准备态以开始提取／开始分析为主，添加和编辑为次操作；结果态可将导出作为主操作，再次分析为次操作。删除等危险操作不常驻为大红按钮。数量只强调数字，不把整段提示加粗染蓝。

每个组件至少定义默认、悬停、键盘焦点、选中 / 半选、禁用、加载、错误、空数据。只读不等于将内容全灰掉，历史配置仍应可阅读和复制。禁用原因放在可读说明或可聚焦容器中，不能仅依靠不可聚焦按钮的 title。

## 5. 资料、目录与选择范围

### 5.1 清单职责

资料管理展示资料库与全局勾选；工具左栏展示本次参与分析的资料；添加资料弹窗编辑选择草稿，取消不改变原选择；历史任务资料来自提交快照，只读查看。不得把当前预览、当前查找结果和本次分析范围混为一谈。

工具侧栏用短指引，例如“点击‘添加’选择文件，下方为已选资料。”底部显示“已选 **N** 份资料”；超过一页时显示本页序号或匹配数，不堆叠“可继续添加、核对原文、关联附件”等非必做步骤。

行内保留文件名打开原文、关联附件图标和移出本次资料图标。附件用于关联补充材料，不只是查看。移出不删除资料库文件，资料库删除另有明确确认。信息提取左栏不恢复批量移除工具栏，不对每行重复显示“解析完成”。

### 5.2 本页与全部页

| 操作 | 作用域 | 必须反馈 |
| --- | --- | --- |
| 表头“本页” | 当前页可选文件，不含文件夹 | 全选 / 半选 / 未选正确；其他页不受影响 |
| 表上方“选择全部页（N 份）” | 当前目录、下级范围、搜索、筛选、权限及适用状态的交集 | N 为完整范围可选数量，不能拿已加载数冒充总量 |
| 仅保留本页 | 当前范围只保留本页，其他范围原选择保留 | 不误清其他目录资料 |
| 取消本范围选择 | 清除当前范围，其他范围保留 | 不叫“清空全部” |
| 切换目录 / 翻页 / 查找 | 改变展示集合 | 不静默清空已选、不改变执行范围 |

正式接入后，全选大量资料不能依靠浏览器不受控地拉取所有文件。选择集合、查询快照或排除项由接口协议确定；这里定义交互语义，不要求重建后端。单表角色选择仍为单选，不能因共用选择器而放开多选。

原 `前端代码/components/common/FileSelectDialog.vue:356–357,564–573` 已有 `allowUnparsed` 和解析状态过滤；当前选择器继续按工具约束筛选。弹窗提示“仅解析完成可选”；未解析、解析中、失败、无分析权限的资料不可误加入。确认时复核变化，提示影响数量并让用户重新确认。

### 5.3 目录与上传

“当前目录”包含有效路径，项目空间不得因数据结构不同漏掉空间层级。“包含下级文件夹”紧邻目录范围，开启后不改变资料归属。目录数、文件数和已选数分别计数。

资料管理只保留一个“上传”入口。上传文件夹待上传清单至少有名称、相对路径、类型、大小和可上传状态；类型汇总不能替代文件清单。保留层级、排除项、重名处理、失败重试和上传记录。上传状态与解析状态分开展示。

## 6. 提示词、字段与规则

提取模板定义输出字段，提示词定义分析指令，不能混称方案。公共提示词分场景、功能、系统；机构、个人为同级来源。工具默认选对应系统提示词，可选择适用个人提示词；个人内容不能因换阶段或工具被误覆盖。

信息提取初始无模板、无字段，用户选择模板载入或自行添加；调整后可“另存为个人模板”。至少一个有效字段后才能提交。独立提取模板管理的复制、导出配置直接可见，不能被“移除工具设置导入导出”误伤。

提示词编辑弹窗宽度基线 `min(1120px, 视口宽度 - 28px)`，高度不超过 `min(900px, 视口高度 - 28px)`。标题、来源、阶段、页脚紧凑布置，正文使用剩余高度并内部滚动。多阶段使用紧凑页签，单阶段不重复显示按钮；恢复默认放正文标签行。已有空间报告中，1366×768 首阶段正文约 493–537px 高，1024×480 约 229–267px；这是空间分配证据，不代表所有内容均已验收。

应用只保存本次配置，不直接分析；取消无副作用；恢复默认不覆盖其他阶段。切换提示词涉及配套规则替换时，说明替换范围。历史只读；会议结果后的新风险要求属于下一次风险分析，不回写已完成议题的执行配置。

大量风险点采用分类、搜索、列表与已选视图，显示当前范围、全部页数量。招投标、合同规则不能堆成长标签墙；名称、说明、选中状态可扫描，详细依据和提示词按需展开。过滤和折叠只改展示，不改已选规则。

词云的停用词表示不统计，新词表示按整体识别。原 `前端代码/views/word-cloud-analysis/Index.vue:39–91` 有词库维护和导入，这类业务数据操作应保留，不能被笼统删除“设置导入”误伤。

## 7. 结果、任务与连续核验

任务中心是跨工具记录集合与运行跟踪入口，不是查看结果的必经中转。当前工具完成后直接显示成果，历史记录可恢复相同工具结果页。

| 操作 | 固定含义 |
| --- | --- |
| 查看结果 | 打开该工具特有成果；无结果时说明不可用原因 |
| 任务信息 | 查看状态、资料范围、执行配置、备注和运行信息；不修改历史执行内容 |
| 导出数据 | 选择已有成果、范围和格式；没有成果或权限变化时说明原因 |
| 再次分析 | 复用资料和设置进入可编辑准备态；明确提交后创建新记录，旧记录保持 |

结果差异必须保留：信息提取是字段表与未提取项；会议是**会议时间轴、议题聚类、聚类详情**，并保留参会人员、时间、金额、关键词 / 正则筛选；词云是词频与来源；主题归纳是主题和基础信息；合同、招投标是规则检查和依据；台账工具是候选关系、评分和来源行。

查看原文按证据定位，返回保留筛选、当前行与滚动；连续核验支持上一条 / 下一条，减少反复回表寻找。核验标记和意见与 AI 原始结果分别记录。缺少真实定位信息时展示可获得的来源，不制造页码、坐标和高亮。

失败重试、停止、再次分析要区分。重试针对可恢复失败；停止针对执行中任务；再次分析是新业务执行。费用报告、会议风险报告等尚未生成的成果不能伪装为可下载。

## 8. 输入、可访问性与状态保持

### 8.1 中文和键盘

查找、命名和长文本遵守输入法组合生命周期。`compositionstart` 到 `compositionend` 期间不能重建输入节点或提交，回车选词不是回车保存。当前统一处理位于 `dist/input-composition.js:6–31`；正式 Vue 实施应落到稳定输入组件，避免多个监听器竞争。

主要流程支持 Tab / Shift+Tab。弹窗打开后焦点进入内部，不能落到遮罩后的页面；Esc 关闭后返回触发入口。长弹窗可先聚焦标题，避免初始聚焦把上半部滚走。依据 [W3C 模态弹窗模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)，正式工程需逐组件验证，不能只加 `aria-modal` 就视为完成。

### 8.2 可读和可点击

本项目对普通业务文字采用 ≥4.5:1 的目标；本轮偏浅的 14px 提示文字应整改。依据 [W3C 文本对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。独立点击目标以 ≥24×24 CSS px 为项目底线，主按钮 ≥36px 高，参考 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。这些是实施标准，不是全系统 WCAG 认证声明。

状态不能只靠红绿颜色。附件、移除等图标须有可访问名称、可见焦点与对象提示。分隔条支持方向键调宽、Home 或双击恢复，拖动不能是唯一方式。所有菜单、禁用原因和错误定位对键盘可达。

### 8.3 批量、长文与权限

已选清单分页只是渲染策略，不缩小分析范围。当前清单每页最多 50 份；招投标单位单独分页，项目与角色关联保持。正式数据规模还需验证服务端分页、增量更新和浏览器内存，演示数据不构成生产性能证明。

原文按需加载，编辑配置时保持当前页码、缩放、解析文本滚动和 PDF 会话，不能每改一个字段就销毁预览器或重取原件。长解析文本按需生成，禁止每次 render 构建所有长文节点。

查看、分析、下载、管理、关联权限分别校验。前端隐藏按钮不是授权；执行与导出由后端校验。引用资料沿完整引用链检查权限，不能借解析文本绕过原文限制。

空目录、查找无结果、未选资料、没有字段、解析失败、暂无成果、无权限分别提示，并提供有效下一步。断网保留草稿与已有结果；未知运行状态标记待更新。部分失败保留可用结果和影响数量，不用全屏报错遮住已完成内容。

## 9. 正式前端组件和状态落地

当前原型多个版本脚本依加载顺序覆盖同名函数，`dist/index.html` 是有效组合入口。单搜旧字符串不能判断用户目前看到什么，正式工程也不应照搬这种叠加实现。

| 建议组件 / 状态域 | 职责 | 原型参考 | 实施要求 |
| --- | --- | --- | --- |
| ToolWorkspace / ToolDefinition | 准备、运行、结果骨架及业务定义 | `tool-preparation.js`、`business-flow.js` | 标题、页签和 aria 共用元数据 |
| MaterialPicker / SelectionScope | 适用性、本页、全部页、目录范围、选择草稿 | `picker-range.js`、`library-range.js` | 复用原 FileSelectDialog 协议，真实总量来自服务端 |
| MaterialList / AttachmentEditor | 本次资料、角色、分页、附件 | `extraction-focus.js`、`bidding-materials.js` | 展示与执行状态隔离，取消不污染主状态 |
| SourceReader | 原件、解析、页码、缩放、放大 | `library-preview.js` | 生命周期稳定，权限及定位来自真实数据 |
| PromptEditor / FieldEditor / RulePicker | 分阶段草稿、字段、规则与复用 | `prompt-guidance.js`、`risk-selection.js` | 共同外框，保留各工具数据结构和校验 |
| TaskRecordActions / ToolResultRouter | 三操作、按工具类型打开成果 | `task-results.js`、`result-actions.js` | 不能把所有工具结果转成同一通用表 |
| EvidenceViewer / ReviewNote | 连续证据核验和人员意见 | `integrated-evidence.js`、`review-notes.js` | 原始结果不可覆盖，意见有人员、时间和版本依据 |
| ThemeTokens / InteractionPrimitives | 字体、颜色、间距、弹窗、菜单、焦点 | `typography.css`、`ui-conformance.css` | 从 token 引用，避免局部新增浅灰破坏对比度 |

至少分离六类状态：服务端实体、当前草稿、提交快照、视图偏好、运行状态、核验意见。列表翻页、缩放和栏宽属于视图状态，不进入业务执行参数。接口适配集中服务层，组件不自行拼装互不一致的任务请求。
