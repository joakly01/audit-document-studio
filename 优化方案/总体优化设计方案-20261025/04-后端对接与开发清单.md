# 后端对接与开发清单

> 核对日期：2026-10-25。原型基线：`2e7b0b29450609b156674e413364ee0d150cda74`，静态资源版本 `20261024.80`。本章依据实际读取的原前端摘录与当前原型代码编制；未取得后端仓库、接口运行环境或全量 API 文档。“存在前端调用”不等于“已验证服务端实现”。

## 1. 结论与改造边界

此次优化以**复用现有业务接口、整理前端状态和结果适配层**为主。目录、文件预览、附件、提示词、提取模板、任务列表、任务详情、失败重试、部分结果导出，在原前端已有明确接口封装。改名、步骤合并、布局调整、紧凑工具栏和操作位置统一，本身不需要新建后端系统。

应优先处理**执行语义与结果可信度**：选择范围是否准确、任务类型是否路由正确、费用单位是否一致、历史配置是否不可变、停止操作是否真的停止后台工作，以及分析发现能否关联真实来源。

当前交互原型是静态可操作原型。`dist/config-schema.js` 的 `configurationFragment()` 明示为诊断映射、不发请求；`analysis-workflow.js`、`prepaid-workflow.js` 以本地状态和定时器演示阶段变化。原型中的规则计算、核验标记、文件导出，不构成真实 AI 执行、后端权限、并发调度及跨用户存储已经完成的证明。

### 工作分类

| 标记 | 含义 | 开发处理 |
|---|---|---|
| R：现有调用可复用 | 原源码有接口封装或明确组件调用 | 对照真实服务联调，保留原参数与业务语义 |
| F：前端适配 | 可通过组件、状态、校验、响应转换完成 | 不因 UI 调整要求新增接口 |
| C：服务能力待确认 | 摘录不完整，或调用不能证明服务行为 | 先核对 OpenAPI、控制器、响应与测试，再判断是否开发 |
| E：建议补充能力 | 原型需要而摘录未见持久接口或明确契约 | 确认缺失后优先扩展已有接口；本章不虚构现有 URL |

**P0**：真实数据接入前必须澄清或修复，涉及范围、结果、金额、权限或操作正确性。**P1**：规模化使用和日常效率。**P2**：后续增强。P0 不代表全部需要增加后端接口。

| 待摊等待基数（P0/R/F） | `awaiting_billing_base` 是用户待办，不是卡死/失败 | 可恢复原任务续算，不重复生成计算任务 |
| 工具内看进度与结果（P1/F/C） | 工具与任务中心共用任务 ID；请求超时和执行失败分开 | 离开/刷新后恢复；超时先查询已有任务，不立即重复创建 |
| 轮询可靠性（P1/F） | `useTaskPolling.js:46` 首轮即终态后仍继续建 interval，需提前返回；异步 setInterval 加 in-flight 或递归 timeout | 慢响应不堆请求；网络失败不改业务状态；终态和卸载无残留请求 |
| 幂等提交（P1/C→E） | 确认创建接口是否支持幂等标识，不足再扩展；防双击仅辅助 | 双击、网络重试不生成意外重复任务 |
| 规模与配额（P1/C） | 核实队列上限、并发、文件页数/文本量限额；已有 `max_concurrent` 不等于完整调度 | 批量任务不会拖垮其他用户；单元失败隔离，有可操作超限提示 |
| 排队预估（P2/C） | 有真实队列位置/统计才给预估，否则显示排队和已等时间 | 不展示未经计算的倒计时 |

### 5.2 长文档与大结果

- **F/P1**：预览按需加载，切文件释放旧会话；原文加载不阻塞字段/规则编辑；返回结果保留筛选、分页与滚动位置。
- **R/C/P1**：复用文件分页、任务目录分页、单条结果详情。若结果仍为全量长文本，优先扩展既有查询的摘要与分页选项。
- **C/P1**：核实预览 URL 有效期、鉴权、Range、CORS、内容类型，以及 doc/xls 转换后原始 ID 映射；公共演示文件预览通过不证明生产鉴权文件可用。
- **R/C/P1**：会议已有 `filterAnalysisResultsAPI()`，参数为日期、人员、金额、关键字、正则。服务分页的结果不能仅过滤当前页；筛选已有结果不触发重新分析。
- **R/F/P1**：大导出优先现有异步合并导出；明确全部结果或当前筛选，不只下载当前页却称全部。导出失败不改源分析任务状态。

### 5.3 不需新建接口的调整

步骤标题、单行原文工具栏、去掉收起原文、统一上传入口、三个任务文字操作、区分本页/全部页、中文输入法 composition 保护、放大提示词编辑区、结果页去固定资料清单、再次分析进入草稿、两栏/三栏布局与表单就地校验，均属前端责任。

## 6. 最小数据契约建议

以下是**评审目标字段，不是已存在的接口定义**。先从现有响应映射，缺失时再扩展。

| 对象 | 最低信息 | 用途 |
|---|---|---|
| 任务摘要 | 稳定 ID、业务/工具类型、名称、提交/开始/完成时间、状态、阶段、成功/失败/待处理数量、结果可用标志 | 工具内与任务中心显示一致；避免已完成但结果不可读 |
| 输入快照 | 实际确认的文件 ID 集、版本或内容校验、空间、附件、排除项、解析状态核验结果 | 跨页选择、历史范围可说明 |
| 配置快照 | 提示词 ID+执行全文+版本、字段/规则/启用项、参数/单位/枚举、配置版本 | 查看任务信息、再次分析；模板后来变更不影响历史 |
| 任务关联 | 来源任务 ID、重试批次/执行单元 ID | 区分失败重试和再次分析 |
| 失败单元 | 稳定 ID、源文件/项目/规则、阶段、错误分类、可重试标志 | 保留成功部分，提供定向恢复 |
| 证据 | 稳定文件 ID、实际摘录；有能力时提供文件版本、页码、文本块 ID 或位置坐标 | 可靠核验；无定位数据时只打开文件 |
| 表格来源 | 工作表、原始行号或记录 ID、原字段、单位、A/B 表身份 | 工程/两表的逐项回溯，避免用同名项目当主键 |
| 核验意见 | 任务/结果 ID、来源版本、核验人、标记、说明、时间、乐观锁版本 | 跨设备留痕，不覆盖 AI 原输出 |

结果适配应保留各工具原 JSON/Markdown/结构化数据；公共摘要与展示字段另行转换。**未返回的页码、金额、条款、日期和匹配理由，不用演示值补齐。** 空金额不等于 0，缺日期不补今天，缺证据不自动关联第一份资料。

费用运算与舍入由服务端按确认后的规则执行。会议阈值 0–1、UI 百分比、工程总分 0–5、字段预筛比例各自显式转换；不以文案或按钮序号推导业务枚举。

## 7. 实施顺序与交付门槛

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| A：契约确认 | 补专用 API、十一工具真实样本；确认单位、类型、范围、取消、附件 | 请求/响应样例与枚举/单位表；所有 P0/C 有负责人和结论 |
| B：前端接入 | 原 Vue 工程复用新流程与 UI；工具适配器复用原规范化函数 | 真实提交/加载/导出贯通；不把静态原型多层覆盖脚本直接作为生产架构 |
| C：必要服务补充 | 仅补 A 确认缺失的快照、取消、证据、核验持久化等 | 兼容方案、旧数据策略、权限和幂等验收 |
| D：业务验收 | 十一工具分别测成功、失败、部分完成、重试、再次分析、来源、导出 | 真实文件和真实后端通过，不只测按钮能点 |
| E：规模验收 | 多用户多任务、长文档、大目录、多规则、大结果、弱网、失权 | 先明确规模与延迟目标，记录实测；不把演示数据流畅作为性能结论 |

可先用信息提取、会议纪要、招投标作为契约联调样板（不改变总体回迁的依赖顺序），分别验证字段型、分阶段聚类型、项目多文件规则型；共用任务与证据层通过后再覆盖其余工具。

## 8. 必测案例

1. **选集**：跨页全选后取消，跨目录添加，含子目录且解析状态混合；确认清单、请求、实际执行、结果、导出一致。
2. **提示词/模板**：系统默认切个人并编辑；之后改名/删除提示词，历史仍有原正文；另存个人模板不覆盖系统模板。
3. **任务分发**：同时有会议、招投标、待摊任务；三个操作“查看结果、任务信息、导出数据”均指向正确工具。
4. **失败与阶段**：10 份失败 2 份，仅重试 2 份；主题后段失败、会议风险未执行、待摊等基数，各自提示正确下一步。
5. **来源**：同名文件、附件、多页证据、两表双边证据均按 ID 找到；缺位置明确降级。
6. **单位/空值**：固定金额样例人工复算；百分比、0–1、0–5 不混；缺金额与 0 在筛选/导出中不同。
7. **再次分析**：只创建可编辑草稿；取消不产生任务；提交新 ID；原结果/附件/配置不变。
8. **权限/停止**：失权后直接请求来源和导出被拒；如提供停止，刷新与另一会话能确认真实终态。
9. **核验意见**：正式交付该能力时，换设备仍在，结果排序不导致标记错位，AI 原结果不变。
10. **大批量**：分页/虚拟列表不缩小执行全集；真实高并发与长文档有测量记录。
