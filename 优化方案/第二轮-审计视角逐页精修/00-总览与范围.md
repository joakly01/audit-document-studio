# 文档挖掘助手：审计视角的逐页精修

版本：V0.2，2026-10-17。设计约束：保留工具与后台主流程，以小改动解决首次理解、顺畅操作和结果阅读。此版是本轮实施建议；上一版中的统一工作台重组、选集快照等作为后续方向，不作为本轮前置。

## 1. 先定义这个工具在审计工作中负责什么

审计人员收到的通常不是一份可直接回答问题的材料，而是一批分散在目录中的合同、会议纪要、项目台账、招投标文件及其附件。其工作不是“使用某个模型”，而是：

1. **搞清资料范围**：是哪一个项目、哪些期间、哪些单位的资料；有没有少选或混入其他项目。
2. **把材料整理成可读信息**：重要字段成表，会议按时间和议题梳理，项目记录建立对应关系。
3. **围绕审计关注事项找线索**：合同条款是否需要进一步核验、项目是否疑似重复、不同表中的项目是否对应。
4. **回到材料核实**：判断某个值或疑点依据的是哪份文件、哪段原文；资料没有说的内容不能误当成没有问题。
5. **把可用成果带走**：导出提取表、分析报告或对照结果，继续人工核实与后续审计工作。

因此，助手的产品定位是：**帮助审计人员整理资料、发现线索、核对来源的分析工具集合。** 不是要求用户先学提示词工程，也不把模型输出直接包装成已经确认的审计结论。

这五类工作不是必须顺序点击的向导。用户可以直接抽取合同、直接看会议纪要，也可以只做两表对比。需要统一的是资料和结果的表达方式，而不是强行把所有工具变成同一个步骤表单。

## 2. 十一个工具各自回答什么问题

以下是工具入口应传达的业务语言，具体输出以已有接口为准。

| 工具 | 审计人员的问题 | 输入 | 看得见的输出 | 与相近工具的边界 |
| --- | --- | --- | --- | --- |
| 信息提取 | 这些材料中的关键内容能否整理成表？ | 文档/目录、提取模板或字段 | 字段值、文件对应关系、可用的来源信息 | 负责取信息，不默认作风险判断 |
| 词云分析 | 这批材料主要反复谈什么？ | 文档、停用词/新词、展示数量 | 词云和词频表 | 高频不是高风险；适合快速熟悉资料 |
| 主题归纳 | 这些文件主要涉及哪些事项？ | 文档、提取与归纳模板 | 基础信息表、归纳文本 | 当前是表格与文本输出，不假装已有可追踪的主题关系库 |
| 时间轴分析 | 这些文档反映的事项先后是什么？ | 含日期与事项的文档 | 日期、文档/事项、摘要 | 不把上传时间当业务日期，不承诺自动补齐所有履行事件 |
| 通用风险点分析 | 按我的关注点，这些材料有哪些待核验线索？ | 文档、风险模板、关注点 | 按文件/关注点组织的分析结果 | 专业工具不适合时的通用入口；不等同跨文件推理 |
| 会议纪要分析 | 历次会议讨论了什么，同类议题怎样变化？ | 一批会议纪要 | 会议时间轴、议题归类、风险报告、问答 | 比一般主题归纳多会议和议题语义及后续问答 |
| 合同分析 | 合同中的具体条款如何对应检查规则？ | 合同及附件、合同类型与模板 | 提取内容、判断依据、分析说明、结果、报告 | 比信息提取多规则检查，不能把空白字段当符合 |
| 招投标分析 | 一个项目的招投标资料有哪些需要关注的情况？ | 项目、招标文件、分单位的投标文件、分析模式 | 按项目/规则/单位的结果和证据 | 项目与投标单位归组是必要输入，不能扁平化成普通文档列表 |
| 待摊费用 | 合同怎么约定计费，给定基数后得到什么计算结果？ | 合同、已支持费用类型、计费基数 | 计费约定与计算报告 | 当前代码主要体现工程费用辅助测算，不应按名称误画成会计摊销表 |
| 工程项目数据一致性分析 | 台账中的项目是否疑似重复、存在主子关系？ | 已支持表格、两类模板、列映射 | 重复项目和主子项目结果 | 当前不是全能工程造价/资金一致性审查 |
| 两表项目关联度 | 两张表中哪些记录可能对应？ | 表一、表二、列对应与比较模板 | 关联分组、对应字段、说明 | 匹配候选不等于证明同一项目；不需要恢复大表全文预览 |

工具身份按现有代码去重：`riskPointCheck`、风险点排查等是风险点分析的兼容别名，不另造一个工具；`fileToPdf`在本包承载信息提取流程，不按内部值误标成“PDF转换”。可见工具仍以权限接口为准。

## 3. 为什么用户现在觉得像几个页面拼在一起

问题集中在四个断点：

- **进门不知道选哪个**：只有工具名称，没有“拿什么进来、会得到什么”。
- **进页不知道先做什么**：空结果、长提示词、参数、筛选同时出现；首要操作藏在角落。
- **操作不确定影响什么**：点文件、勾选文件、加目录、移除文件的含义不统一；修改配置是否影响历史结果不清楚。
- **做完不知道结果在哪里**：结果窄、原文大，或者被带到任务列表；空结果、未执行、筛选无命中、执行失败外观相近。

应优先修复这些断点，保留现有可用的预览、树、结果组件和后台调用。

## 4. 最小改动原则

### 本轮就做

1. **保留三栏和现有全屏工具页**。多数工具继续左侧资料、中间预览、右侧配置/结果；两表维持现有两栏；会议与招投标保留专业布局。
2. **统一页面标题下一句说明**：“添加什么 → 做什么 → 得到什么”，内容不超过两行，首屏长期可见，不做冗长教程。
3. **保留多数工具左下的执行位置**，统一名称“执行”，紧邻显示执行范围和未完成项。添加文件移到左栏标题下，方便首次发现。两表现有右上执行可保留，紧邻配置摘要，不为统一而迁移整页。
4. **调整显隐与顺序**：模板优先，正文和高级参数折叠；首次空态聚焦下一步；完成后切到已有结果Tab并提供展开结果。
5. **把关键状态留在页面上**：已加入数、被排除数、未就绪原因、任务阶段、当前筛选。不能只靠几秒钟消息通知。
6. **用已有结果字段改善阅读**：短摘要、详情展开、冻结关键列、原文入口；不要求模型新增整套输出。

### 不作为本轮的必需改造

不新增全系统工作流编排、不重做权限体系、不要求新选集平台、不更换组件库、不重做后端分析算法，不承诺OCR或模型质量已经解决。新的证据坐标、跨工具结果联动、任意主题表导入、人工核验持久化分别列为能力补充，不能成为本轮交互优化的依赖。

所有页选择若已有目录筛选载荷可准确表达，直接复用；搜索结果跨所有页若现有协议不能表达，就明确限制该入口并说明范围，不能用取当前页冒充所有页。任务超时先修正前端反馈，幂等查询增强单独评估。

## 5. 对上一版的明确收敛

| 上一版方向 | 此版处理 |
| --- | --- |
| 统一重构工作台壳 | 改为先局部修现有组件、布局和显隐，不以重构为前提 |
| 风险分析可能描述为按文件/跨文件 | 更正：现有两种遍历均逐文件处理，仅调用粒度和结果组织不同 |
| 主题关系表与主题导入作为主界面 | 当前先保留提取表+归纳文本，指定主题以已有prompt承载时需验证；结构化导入另列 |
| 统一原文高亮 | 有定位数据就定位，只有文件/片段就展示已有来源，不补造字段 |
| 所有页面完成后整体改布局 | 优先切结果Tab、折叠配置、使用已有隐藏预览/全屏能力，按工具调整 |
| 选集快照、幂等为整体前置 | 作为后续可靠性增强，本轮先让范围和受理状态表达真实 |
