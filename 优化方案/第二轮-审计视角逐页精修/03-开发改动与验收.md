# 开发改动、证据覆盖与验收

## 1. 改动等级

| 等级 | 定义 | 本轮策略 |
| --- | --- | --- |
| L1 展示精修 | 文案、顺序、默认展开、列宽、按钮层级、空态 | 全工具实施，不影响后台协议 |
| L2 交互修整 | 选择暂存、管理勾选、请求状态、Tab联动、参数校验 | 优先共用组件；验证状态与载荷不发生意外变化 |
| L3 已有接口接入 | 个人提示词保存、阶段重试、任务回显、已有报告 | 根据实际接口接通，不把按钮存在当完成 |
| L4 能力扩展 | 幂等查询、全新主题导入、统一精确定位、人工核验留痕 | 单列后续，不阻塞本轮小改 |

“尽量小改”指保留业务调用、组件、页面层级，不能保留会使用户误解执行范围或任务状态的问题。第一版就需要修正确性。

## 4. 微文案替换表

| 原表达 | 建议表达 | 使用位置与理由 |
| --- | --- | --- |
| 选择文件 | 添加文件 | 工具工作集；表示追加。资料角色槽首次为添加表一/招标文件 |
| 批量执行 | 执行 | 多数工具；数量由旁边范围表达 |
| 删除文件（前端） | 移出本次分析 | 明确不是删除原件 |
| 已记录待删除 | 已移出N份，可恢复 | 不向业务人员暴露实现细节 |
| 解析结果 | 提取结果/分析结果/对比结果 | 按工具实际产出命名 |
| 功能配置 | 分析设置 | 按页面适用；具体必选项仍保留业务名 |
| 分词数量 | 展示词数 | 当前实际作用是Top-N展示 |
| 议题聚类/聚类详情 | 同类议题/议题明细 | 保留算法，减少理解门槛 |
| 智能体输出 | 提取的计费约定 | 待摊费用，让用户看懂内容用途 |
| 按文件遍历 | 逐文件检查 | 保留真实模式值及完整说明 |
| 按风险点遍历 | 逐关注点检查 | 不改成跨文件推理 |
| 查看结果（已处于结果页） | 去掉重复操作 | 保留必要Tab，不堆按钮 |
| 任务创建成功（超时推断） | 正在确认提交结果 | 成功必须来自回执 |
| 暂无数据 | 按状态细化 | 无资料、未执行、筛选无命中、结果为空、加载失败不同 |

命名统一不是全局字符串替换：源文件管理中的“删除文件”仍表示真实删除；只在工具工作集中改为移出。

## 6. 交付顺序

1. **先统一可理解性与真实反馈**：全工具说明、空态、名字、模板折叠；同时修执行范围、超时成功。不是只打磨信息提取而留下其他页面。
2. **以信息提取验证共用组件**：选文件、追加/移出、目录管理、执行摘要、预览；迁移所有复用侧栏工具，不改专业结果结构。
3. **逐工具完成局部精修**：会议三页、合同、招投标、费用、两类表格工具，逐页按本规格评审。
4. **补已有接口闭环**：个人提示词、阶段重试、导出与历史恢复；L4独立排期。

无完整工程和人员投入评估，本稿不编造工期。完成一页的定义是首次、准备、运行、成功、失败/空结果都可解释，不是只完成一张成功截图。

## 7. 验收：从未用过的人是否能独立完成

### A. 首屏理解

让未参与开发的审计使用者只看页面，回答“这个工具解决什么问题、资料从哪加、必填是什么、结果会在哪”。记录不能理解的词和误点位置；不由评审人讲解后再判通过。

### B. 完整任务

按工具规格末尾的11个任务执行。关键通过条件：加入的范围与实际执行一致；不用猜主按钮；能找出一个结果的真实来源；知道哪些没处理；能返回先前结果；导出范围可解释。风险类知道结果是待核验线索，费用类不填错单位，表格类不会把表一表二认反。

### C. 必须覆盖的交互边界

- 勾选当前页再翻页、所有页再排除一份、取消添加弹窗、父子目录去重、追加相同文件。
- 打开工具继承资料、不支持格式、未解析文件、权限变化、目录计数失败。
- 快速切文件与迟到预览响应、改模板未保存、切Tab保留焦点和筛选。
- 请求超过等待阈值、迟到成功/失败、刷新任务状态失败、部分失败但其他仍运行。
- 会议基础成功但风险失败；费用提取成功但待填基数；主题提取成功但归纳失败。
- 两表字段缺失、金额单位不同、结果只有候选时不能生成未经证实的未匹配数。
- 任务详情返回保留列表页码；下载链接失效、报告生成失败、合并导出条件不满足。

### D. 实现核对

在完整工程运行既有相关测试与构建；对选集和状态等变更补有意义的回归验证。对同一输入比较改前/改后提交的工具、资料ID、目录范围、排除项、模板参数，除明确设计变更外应一致。不为文案和折叠额外造大量实现镜像测试。

在1366×768和1920×1080验证操作区、嵌套滚动、长文件名；键盘能打开/关闭弹窗并回焦点。大目录仍按现有分页/虚拟加载，不为线框效果加载整批内容。
